## 1. 핵심 결정 요약

| 항목 | 결정 | 근거(요약) |
|---|---|---|
| 저장 포맷 | **`path`에 `{"type":"polyline"}` 세그먼트 추가**. bezier 피팅은 후속(커뮤니티 공유용 canonical 변환기)으로 연기 | 게임은 어차피 6px 폴리라인으로 재베이크. WYSIWYG(별 꼭짓점 보존). 피팅 품질 리스크 회피. 커스텀은 로컬 전용이라 포맷 단일성 비용이 아직 없음 |

## 2. 저장 포맷 결정: polyline 세그먼트 추가 (안 A)

### 2.1 비교

| 기준 | 안 A: `type:"polyline"` 추가 | 안 B: bezier 피팅으로 기존 포맷 유지 |
|---|---|---|
| 다운스트림 영향 | `TrackData.bake()`에 타입 분기 1개 추가(가산적). 나머지 파이프라인(query·미니맵·FinishView·미리보기) 전부 불변 | 완전 무변경(포맷 단일) |
| 저작 구현 난이도 | 낮음(평활·데시메이트·재샘플만) | 높음(Schneider 피팅 + 코너 검출 + 오차 재분할, ~150줄, 튜닝 필요) |
| WYSIWYG | 그린 대로 재현(재샘플 오차만) | 피팅 근사 오차 — 별 꼭짓점이 둥글어지거나 직선이 흔들릴 수 있음 |
| 파일 크기 | 3000px·6px → 약 500점 ×2 = 수 KB | 세그먼트 수십 개, 작음 |
| 결정론 | polyline→bake 재샘플이 결정론적(입력 고정 시 동일) | bezier→bake 결정론적. 단 피팅 자체는 저작 시 1회 |
| 서버/커뮤니티 호환 | 스키마 확장 필요(후속) | 즉시 호환 |

### 2.2 결정과 근거

**안 A 채택.** 근거:

1. **게임 판정은 이미 폴리라인 기반.** `bake()`는 bezier/polyline 모두 6px 폴리라인으로 변환(`TrackData.gd:33`). 유저 체감은 폴리라인 → bezier 피팅 후 재폴리라인화는 근사 오차 이중 누적.
2. **정체성 = WYSIWYG.** 핵심은 "하트·별 모양을 유저가 직접". 피팅이 꼭짓점 둥글림·곡선 흔들림 → 정체성 훼손.
3. **구현 리스크 배분.** 한정 예산은 피팅 수학보다 **드로잉 UX + 검증**에(사용자 체감·안정성 좌우). 피팅은 실패 시 디버깅 난해, 재샘플은 자명.
4. **포맷 단일성 비용 아직 없음.** 커스텀은 로컬 전용(§7.4). 서버 검증·커뮤니티 교환은 후속 → 그때 polyline→bezier **canonical 변환기** 별도 부착(§13). polyline 트랙은 이후에도 계속 로드(가산적).
5. **확장이 가산적.** `bake()`는 현재 `type` 미검사, p0 ~ p3만 읽음. 타입 분기 추가는 기존 bezier 경로 불변.

### 2.3 확장된 포맷

```json
{
  "track_id": "custom_ab12cd34",
  "name": "My Heart",
  "difficulty": "normal",
  "fabric": "cotton",
  "length": 2980,
  "width": { "perfect": 18, "safe": 42, "fail": 90 },
  "path": [
    { "type": "polyline", "points": [[-227,313],[-233,305], ...], "closed": false }
  ],
  "modifiers": [],
  "is_custom": true,
  "checksum": "sha256:....",
  "editor_version": "0.1.0"
}
```

- `path`는 polyline 세그먼트 1개(단일 스트로크) 또는 여러 개(다중 스트로크 이어붙임).
- `points`는 저작 시 균일 재샘플(≤6px) 좌표. `bake()`가 다시 ≤6px 보정 → 간격 다소 커도 안전.
- **`closed`는 `bake()`/`query()`가 소비 안 함 — 순수 저작/재편집 힌트.** 현행 아키텍처에 "폐곡선" 판정 개념 없음. heart_01·star_01도 실은 시작·끝이 기하적으로 가까운 **open path**(TrackData.gd:12-16 주석), s·피니시는 항상 선형 처리. 유저가 "루프 닫기" 켜도 저장 `points`는 갭 둔 open 폴리라인(§9), `closed`는 에디터로 **다시 열어 편집 시 UI 상태 복원**용에 국한. 소비처 없는 필드가 꺼려지면 v1에서 생략 무방(시작/끝 근접으로 재추론). **`bake()`가 `closed=true`를 보고 끝→시작 잇게 만들지 말 것** — 피니시 깨짐(§9).
- `width`는 난이도 프리셋에서 채웁니다. 불러온 파일의 폭이 프리셋과 다르면 사용자 지정 폭으로 그대로 보존합니다(§4.6).
- `items`는 `[{"s", "type", "lat"}]` 형식이고, type은 `thimble`(골무)과 `autopilot`(엄마 찬스)만 씁니다. 에디터의 아이템 도구(§4.5)로 배치하며, 저장·불러오기·내보내기에서 보존합니다.
- `modifiers`는 게임이 소비하지 않습니다. 에디터는 항상 빈 배열로 저장하고, 불러온 파일에 비어 있지 않은 `modifiers`가 있으면 제외했다는 사실을 안내합니다(§8.1).
- 공식(bezier)·커스텀(polyline)이 **같은 `path` 스키마에 영구 공존**(로드 시 몰래 bezier 변환 금지 — §2.5). 정책상 공식=bezier / 커스텀=polyline 운용.

### 2.4 `bake()` 확장 (의사코드 — `TrackData.gd` 수정)

```gdscript
func bake(path_json: Array) -> void:
    points = PackedVector2Array()
    s_arr = PackedFloat32Array()
    for seg in path_json:
        match str(seg.get("type", "bezier")):
            "polyline":
                _bake_polyline(seg)     # 신규
            _:
                _bake_bezier(seg)       # 기존 로직을 이 함수로 추출(동작 불변)
    length = s_arr[s_arr.size() - 1] if s_arr.size() > 0 else 0.0

func _bake_polyline(seg: Dictionary) -> void:
    var raw: Array = seg.get("points", [])
    for k in range(raw.size()):
        var q: Vector2 = _to_vec(raw[k])
        if points.is_empty():
            _append(q); continue
        var last: Vector2 = points[points.size() - 1]
        if k == 0 and last.distance_to(q) < 0.01:
            continue                     # 이전 세그먼트 끝점과 공유 → 중복 제거
        # 긴 간격은 ≤ BAKE_INTERVAL(6px)로 잘게 나눠 넣어 query 윈도 가정을 지킨다.
        var n: int = maxi(1, ceili(last.distance_to(q) / BAKE_INTERVAL))
        for m in range(1, n):
            _append(last.lerp(q, float(m) / float(n)))
        _append(q)
```

> **함정(재샘플).** `query()`의 `FWD_WIN=12`·`RELOCALIZE_FWD_WIN=40`은 점 간격 ≈6px 전제 → "앞 72px / 240px" 의미. 재샘플 없이 30px 간격 그대로 넣으면 같은 인덱스 윈도가 360px·1200px 앞을 봄 → 추적 거동 변화. **`_bake_polyline`은 반드시 ≤6px로 세분.**

### 2.5 로드 시점 자동 정규화 금지 (결정론)

polyline 트랙을 **로드 시점에 몰래 bezier로 변환 금지.** 피팅/평활 알고리즘은 버전별 결과 미세 상이 → 로드마다 재변환하면 같은 저장 파일이 버전업 후 **모양·플레이·(후속)리플레이가 조용히 달라짐**(결정론 드리프트). polyline은 저장 그대로 `bake()`에서 결정론적으로 폴리라인화. bezier 변환은 필요 시(커뮤니티 공유·서버)에만 **명시적 "export/canonicalize" 단계**(§13)에서 저작 시 1회, 유저 인지 하에 수행.

## 3. 에디터 씬 / 노드 구조

- 좌표는 항상 월드 단위로 저장하고, 그릴 때만 화면 좌표로 바꿉니다(`screen = world·zoom + pan`).

## 4. 에디터 UX 흐름

기본 흐름은 `그리기 → (아이템 배치) → 검증 → 이름·난이도·원단 → 저장 → 테스트 플레이 → 편집으로 돌아가기`입니다.

### 4.1 도구

| 도구 | 조작 | 동작 |
|---|---|---|
| 그리기 | 왼쪽 드래그 | 자유곡선을 그립니다. 경로가 이미 있으면 끝점(노란 점) 근처에서 시작해야 이어 그려집니다. 끝점에서 먼 곳에서 그리면 기존 경로를 바꾸지 않고 "이어 그리기는 끝점에서 시작하세요"라고 안내합니다. |
| 화면 이동 | 왼쪽 드래그 | 카메라만 옮깁니다. 경로 좌표는 바뀌지 않습니다. |
| 끝부분 자르기 | 누르고 떼기 | 누른 지점부터 끝까지 잘라 냅니다. 마우스를 올리거나 누르고 있는 동안 잘릴 구간을 빨간색으로 보여 주고, 함께 지워질 아이템 수를 미리 알립니다. |
| 구간 지우기 | 문지르기(드래그) | 브러시가 닿은 구간만 지웁니다. 문지르는 동안 지워질 구간을 빨간색으로 보여 주고, 손을 떼면 한 번에 지웁니다. 지운 구간이 경로 끝에 닿으면 그 끝을 잘라 내고, 경로 중간이면 경로에 틈이 생깁니다(아래 "틈 잇기" 참고). |
| 아이템 | 누르기·드래그 | 경로 가까이를 누르면 고른 종류의 아이템을 놓고, 마커를 누르면 선택하며, 끌면 경로를 따라 옮깁니다(§4.5). |

- 휠과 가운데·오른쪽 버튼 드래그로도 확대·축소와 화면 이동을 할 수 있지만, 필수 조작은 화면의 버튼입니다. 터치 기기에서는 "화면 이동" 도구와 −/+ 버튼만으로 이동과 확대를 할 수 있습니다.
- 그리기 영역 밖에서 버튼을 떼도 스트로크는 정상적으로 마무리됩니다. 뗌 이벤트를 놓치거나 포커스를 잃으면 진행 중이던 입력을 버리므로, 그리기 상태가 남지 않습니다.
- 스냅·자르기·지우기 브러시·아이템 선택 반경은 화면 px 기준으로 정한 뒤 현재 배율의 월드 거리로 바꿉니다. 그래서 최대로 축소한 상태에서도 누르기 쉽습니다. 지우기 브러시는 끝부분 자르기와 같은 18px이며 월드 기준으로 22보다 작아지지 않습니다. 배율이 0.04이면 450, 0.15이면 120, 1.0이면 22입니다.

#### 구간 지우기와 틈 잇기

- 끝에서부터 조금씩 문지르면 문지른 만큼만 끝이 잘립니다. 예전 지우기 도구처럼 끝을 조금씩 줄이는 조작을 같은 횟수의 드래그로 할 수 있으며, 지우기 한 번(누름부터 뗌까지)이 실행취소 한 단계입니다.
- 시작 쪽을 지우면 시작점이 옮겨집니다. 문지르는 동안 새 시작점을 초록 원으로 미리 보여 주고, 상태줄에서도 시작점이 옮겨진다고 알립니다.
- 경로 중간을 지우면 경로에 틈이 생깁니다. 틈의 두 끝점은 빨간 점으로 표시되고, 두 점 사이는 빨간 점선으로 이어서 보여 줍니다. 끝점 둘레의 고리는 이어 그리기 스냅 반경을 나타냅니다.
- 틈은 그리기 도구로 잇습니다. 한쪽 끝점 근처에서 시작해 다른 쪽 끝점 근처에서 끝나는 스트로크를 그리면, 그 사이가 새 스트로크로 채워져 경로가 하나로 이어집니다. 어느 쪽 끝점에서 그리기 시작해도 경로의 진행 방향은 그대로 유지됩니다. 스트로크가 반대쪽 끝점에 닿지 않고 끝나면 닿은 쪽 조각만 그린 만큼 늘어나고, 틈은 그대로 남습니다.
- 틈 안내 줄(GapRow)의 "직선으로 잇기"는 두 끝점을 직선으로 잇고, "뒤쪽 버리기"는 틈 뒤쪽 조각을 버려 틈 앞 끝점에서 경로를 끝냅니다. 두 동작은 각각 실행취소 한 단계입니다.
- 틈은 한 번에 하나만 둘 수 있습니다. 틈이 있는 상태에서 다른 중간 구간을 지우려고 하면 경로를 바꾸지 않고, 틈을 먼저 이으라고 안내합니다. 교차 지점처럼 브러시가 두 갈래에 함께 닿는 경우에도 같은 안내가 나오므로, 확대한 뒤 다시 지우면 됩니다. 틈의 끝점 쪽을 더 지워 틈을 넓히는 것은 허용합니다.
- 틈이 있는 동안에는 검증, 저장, 테스트 플레이, 루프 닫기, 자동 수정, 길이 조절, 아이템 배치를 할 수 없고, 누르면 상태줄에 사유가 표시됩니다. 끝부분 자르기와 Backspace는 틈 뒤쪽 조각의 끝에서 동작하며, 틈 앞쪽을 누르면 뒤쪽 조각까지 함께 잘립니다. 틈 상태는 실행취소·다시 실행, 저장 상태 표시(항상 "틈 있음 · 저장 불가"), 테스트 복귀 스냅샷에 포함되지만 저장 파일에는 기록되지 않습니다.
- 닫힌 루프에서 구간을 지우면 루프를 연 뒤 같은 규칙으로 지웁니다. 루프 닫기는 틈을 이은 뒤에 다시 켤 수 있습니다.
- 문지르는 도중에 포커스를 잃거나, 그리기 영역 밖에서 손을 떼거나, 도구를 바꾸거나, 실행취소를 누르면 지우기를 취소하며 경로는 바뀌지 않습니다. 터치 기기에서는 한 손가락 드래그로 같은 도구를 씁니다.
- 캔버스는 화면 4px마다 원시 점을 받습니다. 축소한 상태에서는 원시 점 간격이 월드 단위로 커지므로, `StrokeProcessor`가 Catmull-Rom 보간으로 점을 채우고 평활 창을 원시 간격에 비례해 넓힙니다(§5).

### 4.2 화면(카메라)

- 새 문서는 0.15 배율로 시작합니다. 수동 축소와 전체 보기는 0.04까지 내려가므로, 허용 최대 길이(8000)의 직선 트랙도 844×390 터치 레이아웃의 그리기 영역에 담깁니다. 격자 간격은 축소할수록 넓어집니다. 트랙을 불러오거나 열면 경로 전체와 판정 폭이 보이도록 "전체 보기"를 적용합니다. 테스트 플레이에서 돌아오면 보던 배율과 위치를 복원합니다.
- ViewBar의 −/+ 버튼은 그리기 영역 중앙을 기준으로 배율을 바꾸고, 현재 배율을 %로 표시합니다. "전체 보기"는 카메라만 조정합니다.
- 키보드에서는 `+`/`=`와 `−`로 배율을 바꾸고 `F`로 전체 보기를 적용합니다.

### 4.3 편집 안전성과 실행취소

| 기능 | 조작 | 동작 |
|---|---|---|
| 실행취소 / 다시 실행 | 툴바, Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z(또는 Ctrl+Y) | 문서 전체를 한 단위로 되돌립니다. 최대 30단계를 보관하며, 연속해서 입력한 이름은 한 단위로 묶고, 드래그는 뗄 때 한 번만 기록합니다. 진행 중인 드래그·스트로크·자르기는 먼저 취소하고, 아이템 선택은 해제합니다. |
| 새로 그리기… | 하단 버튼, Delete | 확인창을 거친 뒤 경로와 아이템을 지웁니다. 이름·난이도·원단은 유지하고, 실행취소로 되돌릴 수 있습니다. |
| 끝 자르기 | Backspace | 마지막 8개 점을 잘라 냅니다. 잘린 구간의 아이템은 같은 undo 단위로 지우고 개수를 알립니다. |
| 루프 닫기 | C, 체크버튼 | 끝을 시작점 근처에서 끊어 작은 간격을 남깁니다(§9). 닫기를 해제하면 닫기 전 경로로 돌아가며 아이템도 그 경로에 다시 투영합니다. 닫은 상태에서 자동 수정을 적용하면 닫기 전 경로를 비우므로, 해제해도 수정한 경로가 유지됩니다. 길이 조절은 닫기 전 경로도 같은 배율로 옮깁니다. |

- 이름 입력칸에 포커스가 있거나 확인창이 떠 있으면 Ctrl/Cmd+Z, Delete, Backspace 같은 단축키를 캔버스가 가로채지 않고 텍스트 편집에 맡깁니다.
- 저장 상태는 "현재 저장 가능한 문서"와 "마지막으로 저장한 문서"를 비교해 계산하며, 하단의 문서 상태 줄에 트랙 길이·아이템 수와 함께 항상 표시합니다.
- 경로 편집이 아이템에 미치는 영향은 다음과 같습니다. 이어 그리면 기존 s를 유지합니다. 길이를 조절하면 진행 비율을 유지합니다. 끝을 자르거나 구간을 지우면 지워진 구간의 아이템을 함께 지우고 개수를 알립니다. 틈을 잇거나 틈 뒤쪽 조각의 시작을 늘리면 뒤쪽 조각의 아이템은 월드 위치를 그대로 두고 새 경로 기준으로 s만 다시 계산합니다. 시작 쪽을 지웠을 때도 남은 아이템은 같은 방식으로 s를 다시 계산합니다. 새로 그리거나 불러오면 경로와 아이템을 함께 바꾸고, 실행취소로 함께 되돌립니다. 자동 수정처럼 곡률을 고치거나 재샘플하면 아이템의 이전 위치를 새 경로에 투영하고, 크게 옮겨졌거나 가까운 다른 구간과 헷갈리는 아이템은 "검토 필요"로 표시합니다.

### 4.4 검증

- "검증"(Enter)을 누르면 `TrackValidator`(§6)의 결과를 캔버스 마커와 IssuePanel 목록으로 보여 줍니다.
- IssuePanel 제목은 "저장 가능"(하드 규칙 통과)과 "저장 불가"를 구분하고, 권장 경고 수를 함께 적습니다. 항목마다 사유와 해결 힌트가 붙으며, 위치가 있는 항목(급한 곡선, 자기근접)에는 "위치로" 버튼이 있어 카메라를 옮기고 해당 위치를 강조합니다.
- 권장 경고가 많으면 6개까지만 따로 적고 나머지는 한 줄로 요약합니다. 목록은 스크롤되며 접을 수 있습니다. 권장 경고만 남은 트랙은 그대로 저장할 수 있고, 경고를 없애려고 트랙을 강제로 바꾸지 않습니다.
- 이름과 원단을 바꿔도 검증 결과는 유지됩니다. 경로, 난이도, 폭을 바꾸면 검증을 다시 해야 합니다.

### 4.5 아이템 배치 (골무 / 엄마 찬스)

게임에 이미 있는 아이템 두 종류만 쓰며, 저장 형식은 기존 `items` 스키마(`{s, type, lat}`)를 그대로 따릅니다.

1. 툴바에서 "아이템" 도구를 고르고, 아이템 막대에서 "골무" 또는 "엄마 찬스"를 고릅니다. 버튼에는 게임과 같은 아이콘이 표시됩니다.
2. 경로 가까이를 누르면 가장 가까운 선분에 투영한 호길이 s 위치에 아이템이 놓입니다. 새 아이템의 옆 거리(lat)는 0이므로 중심선 위에 놓입니다. 놓은 아이템은 선택되지 않으므로, 종류 버튼을 누르면 다음에 놓을 종류만 바뀝니다.
3. 마커를 누르면 선택되고, 마커 옆과 아이템 막대에 "시작부터 거리 / 트랙 길이 (%)"가 표시됩니다. 교차하거나 가까운 구간에서는 이 거리를 보고 어느 갈래에 놓였는지 확인할 수 있습니다.
4. 선택한 마커를 끌면 경로를 따라 이동합니다. 이동할 때는 직전 s 근처 구간만 다시 투영하므로, 교차점을 지나도 다른 갈래로 옮겨 가지 않습니다. lat은 그대로 유지합니다.
5. 아이템 막대의 "삭제"나 Delete/Backspace 키로 선택한 아이템을 지웁니다. 아이템 도구에서 선택한 아이템이 없으면 이 키들은 아무 동작도 하지 않습니다. 마커를 눌러 선택한 상태에서 종류 버튼을 누르면 그 아이템의 종류가 바뀝니다.

- 배치, 이동, 삭제, 종류 변경은 각각 실행취소 한 단계입니다. 아이템 도구에서는 새 스트로크가 시작되지 않습니다.
- 허브 게시 제약에 맞춰 아이템은 최대 128개까지 놓을 수 있고, s는 0 이상 `트랙 길이 − 0.5` 이하로 맞춥니다. 출발·도착에서 150 이내에 놓으면 경고만 표시하며, 배치를 막지는 않습니다.
- 불러온 파일의 lat 값은 그대로 보존합니다. 난이도를 바꿔 판정 폭(fail)이 줄어든 결과 |lat|가 fail보다 커진 아이템은 값을 조용히 바꾸지 않고 "검토 필요"로 표시합니다.
- "검토 필요" 아이템은 빨간 테두리로 표시되고, 하나라도 있으면 저장과 테스트 플레이가 막힙니다. 아이템 도구로 그 아이템을 옮기거나 "이 위치로 확정"을 누르면 하나씩 해결되고, ReviewRow의 "지금 위치로 확정"을 누르면 한꺼번에 해결됩니다. 개별 확정과 일괄 확정은 검토 사유와 관계없이 같은 규칙으로 s와 lat을 저장 가능한 범위 안으로 맞춥니다.

### 4.6 이름 · 난이도 · 폭 · 원단

| 필드 | 값 | 비고 |
|---|---|---|
| 이름 | 1~24자 | 비워 두면 "Custom Track"으로 저장합니다. |
| 난이도 | 초급(Beginner), 보통(Normal), 숙련(Expert), 마스터(Master) | 난이도를 고르면 그 난이도의 폭 프리셋이 적용됩니다. |
| 폭 | perfect/safe/fail | 프리셋이면 "폭 18/42/90 (보통 프리셋)"처럼, 불러온 파일의 폭이 프리셋과 다르면 "사용자 지정 폭 15/38/80"처럼 표시합니다. |
| 원단 | 면·데님·실크·니트·울·펠트·새틴·가죽 | 내부 id(cotton…leather)는 그대로 저장합니다. 선택 즉시 옆의 견본과 주행 특성 문구가 바뀝니다. |

난이도별 폭 프리셋은 다음과 같습니다.

| 난이도 | perfect | safe | fail |
|---|---:|---:|---:|
| 초급(Beginner) | 22 | 52 | 108 |
| 보통(Normal) | 18 | 42 | 90 |
| 숙련(Expert) | 14 | 34 | 72 |
| 마스터(Master) | 12 | 28 | 60 |

- 사용자 지정 폭은 난이도를 직접 고를 때만 프리셋으로 바뀝니다. 이때 상태줄에서 바뀐 폭과 이전 폭을 알려 주며, 실행취소로 되돌릴 수 있습니다.
- 원단 이름과 견본은 트랙 선택 화면과 같은 표(`TrackSelectScreen.FABRIC_LABELS`)와 `FabricSurface.swatch_source`를 씁니다. 전용 타일이 없는 원단(펠트·새틴·울·가죽)은 게임 바닥과 같은 대표색으로 견본을 그립니다. 저장한 원단은 테스트 플레이의 바닥과 주행 특성에 그대로 적용됩니다.
- 견본 옆에는 `FabricProfile.describe`가 돌려주는 주행 특성 문구(예: "주행: 조금 빠르지만 반응이 늦고 위험이 더 쌓임")를 표시하고, 마우스를 올리면 속도·조향 지연·위험 누적 배율을 툴팁으로 보여 줍니다. 이 Label은 장면 파일이 아니라 `EditorSession.add_fabric_note`가 코드로 붙입니다. 배율과 적용 방식은 `docs/fabric_profiles.md`에 정리했습니다.

### 4.7 트랙 길이 조절 · 자동 수정

- "트랙 길이 조절…" 대화상자는 현재 길이, 목표 길이(기본값은 현재 길이), 배율, 적용 후 예상 길이, 예상 검증 결과를 보여 줍니다. 목표를 바꾸면 경로 중심을 기준으로 균일하게 스케일하고 6 간격으로 재샘플한 결과를 청록색 선으로 미리 보여 주며, "적용"을 눌러야 좌표가 바뀝니다. 적용은 실행취소 한 단계이고, 취소하면 원본이 그대로 남습니다.
- 긴 트랙을 자동으로 줄이지 않습니다. 6000처럼 권장 범위(2500~4500) 밖이어도 허용 범위(1500~8000) 안이면 경고만 표시되고 저장할 수 있습니다. 2500보다 짧은 트랙에는 "권장 최소 2500으로 늘리기" 버튼을 제안합니다.
- 길이를 조절해도 원단과 판정 폭은 유지되고, 아이템은 진행 비율을 유지하며 lat과 closed 상태도 유지됩니다. 반경이나 선 간격이 좁아져 검증에 실패할 것으로 예상되면 적용 전에 사유를 보여 줍니다.
- "자동 수정…"은 급한 곡선을 둥글게 고친 결과를 확인창과 청록색 선으로 먼저 보여 주고, "적용"을 눌렀을 때만 반영합니다. 적용하면 아이템을 새 경로에 다시 투영합니다(§4.3).

### 4.8 저장 · 테스트 플레이 · 편집 복귀

- 저장하려면 경로에 틈이 없어야 하고, 검증을 통과하고 아이템이 실제 제약(최대 128개, 종류, 0 ≤ s ≤ 트랙 길이 − 0.5, |lat| ≤ fail)을 지키며 "검토 필요" 아이템이 없어야 합니다. 저장 직전에는 실제로 저장될 경로(0.1 격자, 중간점 삽입)를 베이크해 한 번 더 검증하고, 아이템 s 상한도 그 경로의 길이로 확인합니다. 여기서 실패하면 저장하지 않고 사유를 보여 줍니다. 처음 저장하면 새 `custom_` id를 받고, 그 뒤로는 같은 파일에 저장합니다. 공식 트랙이나 허브에서 받고 편집하지 않은 트랙을 열면 원본은 그대로 두고 사본으로 편집하므로, 저장하면 새 로컬 트랙이 됩니다.
- "테스트 플레이"를 눌렀을 때 저장하지 않은 변경이 있으면 "저장 후 테스트" 확인창이 나타나며, 저장에 실패하면 출발하지 않습니다. 출발하기 전에 편집 문서, undo/redo, 배율과 위치, 선택한 도구와 아이템을 메모리 스냅샷으로 보관합니다. 이 스냅샷은 앱을 다시 실행하거나 브라우저를 새로 고치면 사라집니다.
- 테스트 결과 화면의 주 버튼은 "편집으로 돌아가기", 보조 버튼은 "다시 테스트"입니다. 일시정지 메뉴에도 "편집으로 돌아가기"(M)가 있고, 재시작(R)은 테스트 상태를 유지합니다. 돌아오면 스냅샷을 복원합니다.
- 테스트 플레이는 결과 통계만 보여 주고, 개인 최고 기록과 공식 서버 제출은 하지 않습니다. 결과 화면에도 "테스트 플레이는 기록을 저장하지 않습니다"라고 표시합니다.

## 5. 드로잉 파이프라인 (raw → smooth → decimate → resample → path)

`StrokeProcessor`(RefCounted). 원시 점 배열 → 저장 가능한 polyline 세그먼트.

```gdscript
# StrokeProcessor.process(raw: PackedVector2Array, closed: bool) -> PackedVector2Array
func process(raw: PackedVector2Array, closed: bool) -> PackedVector2Array:
    if raw.size() < 2:
        return raw
    var n := _normalize(raw)           # 0) 정규화: 중복점/0길이 제거, 좌표 quantize, 상한 클램프
    var corners := _detect_corners(n)  # 1) 코너 후보 표시(급격한 방향 전환점 = 별 꼭짓점 등)
    var s := _smooth(n, corners)       # 2) 평활(Chaikin 2회/이동평균 창5) — 코너 인덱스는 보존
    var d := _decimate_rdp(s, 2.0)     # 3) RDP 데시메이트(ε≈2px) — 곡률 노이즈↓
    var r := _resample_uniform(d, BAKE_INTERVAL, corners)  # 4) 균일 ≤6px 재샘플(코너 강제 삽입)
    if closed:
        r = _apply_close_gap(r)        # 5) 끝점을 시작점 근처로(작은 갭 유지, §9)
    return r
```

- **0) 정규화(저장 전 필수)**: 연속 중복점·0길이 세그먼트 제거, 최소 세그먼트 거리(예: 1px) 필터, 좌표 quantize(예: 0.1px 반올림 → 파일·checksum 안정), 점 수·좌표 범위 상한 클램프(악의적/퇴화 입력 차단).
- **1) 코너 검출 & 보존**: 인접 방향 전환각 임계(예: >50°) 이상 점을 **코너 후보로 표시**. 평활·재샘플이 뭉개면 별 꼭짓점 같은 의도된 뾰족함이 6px 샘플 사이에 소실 → **평활에서 코너 인덱스는 이동/제거 안 함, 재샘플 시 코너 좌표 강제 삽입**.
- **2) 평활**: Chaikin(코너 컷) 2회 또는 창 5 이동평균. 픽셀 지터 제거로 이후 곡률 측정이 의도 반영(코너 후보 구간은 약하게).
- **3) 데시메이트(RDP)**: ε≈2px로 직선 구간 점 감소(파일·계산 절감).
- **4) 균일 재샘플**: 호길이 기준 ≤6px 등간격 + 코너 강제 삽입. `bake()` 재샘플과 이중 안전망.
- **5) 닫기 갭**: §9.
- **줌아웃 정규화**: 캔버스가 넘기는 원시 점 간격(`MIN_SAMPLE_PX / zoom`)이 6을 넘으면, 정규화 뒤에 Catmull-Rom 보간으로 4 간격까지 점을 채우고 이동평균 창을 원시 간격에 비례해 넓힙니다(최대 16). 이렇게 하면 0.15 배율에서 그린 곡선도 1.0 배율에서 그린 곡선과 비슷한 모양과 곡률을 갖습니다.

> 평활은 곡률을 **키우는** 방향 → min-radius 검증 통과에 유리. 단 유저 의도 뾰족함(별 꼭짓점)은 평활만으론 min-radius 아래 잔존 → 검증의 **자동 필렛**(§6.2)이 처리. 코너 보존(1)·자동 필렛(§6.2)은 상보: 보존 = "의도한 꼭짓점을 잃지 않게", 필렛 = "너무 뾰족해 주행/추적 불가한 꼭짓점만 최소반경으로 둥글게".

## 6. 검증 규칙

`TrackValidator`(RefCounted). 입력 = 재샘플된 폴리라인 + 판정 폭(width). 출력 = 위반 목록(구간 인덱스·종류·자동수정 가능 여부).

### 6.1 규칙 표

| 규칙 | 임계 | 판정 | 실패 처리 |
|---|---|---|---|
| 최소 점 수 | ≥ 8점 & 유효 길이 | 하드 | 저장 불가("너무 짧음") |
| **최소 곡률반경** | ≥ **28px**(하드), 권장 ≥45px | 하드(권장은 소프트) | **자동 필렛 제안**(§6.2) 또는 위반 하이라이트 |
| **길이** | 권장 **2500 ~ 4500px**. 하드 하한 1500 / 상한 8000 | 권장=소프트, 극단=하드 | "트랙 길이 조절…"(§4.7)로 사용자가 목표 길이를 정해 적용(§6.4). 권장 밖은 경고만 |
| **자기근접** | 호길이-차 기반 2단(§6.3) | 하드/소프트 | 하드는 위반 쌍 하이라이트→재편집 요구. 소프트는 경고만 |
| 시작/끝 분리 | 시작·끝 s가 최대한 떨어짐(open path) | 하드(닫기 시 자동보장) | §9로 자동 처리 |
| 자기교차(선택) | 인접 아닌 세그먼트 교차 없음 | 소프트 | 경고(코리도 겹침 안내). 교차 자체는 자기근접에 흡수 |

기본 임계 상수(추적 윈도에서 유도):

```gdscript
const MIN_RADIUS := 28.0                # 1단 회전반경 24px < 28 → 최저 기어로 주행 가능(여유)
const RADIUS_RECOMMEND := 45.0
const LEN_MIN := 2500.0; const LEN_MAX := 4500.0     # 권장
const LEN_HARD_MIN := 1500.0; const LEN_HARD_MAX := 8000.0
const ARC_EXEMPT := 110.0               # ≈ π·MIN_RADIUS·1.2 : 합법 최소반경 U턴 이웃 면제
const RELOCALIZE_REACH := 300.0         # ≈ RELOCALIZE_FWD_WIN(40)·BAKE(6)=240 + 여유
```

> **곡률 28px 이중 근거.** (a) 주행성: architecture §6.3에서 1단 최소 회전반경 24px, 5단 75px. 28px면 1 ~ 2단으로 모든 커브 추종 가능(24px보다 여유). (b) 추적 안정성: 반경 R U턴의 반호 길이 πR가 `FWD_WIN`(72px)보다 커야 반대편이 정상 윈도에 안 들어옴 → R > 72/π ≈ 23px. 28px는 두 조건 동시 충족.

### 6.2 최소 곡률반경 — 자동 필렛(스무딩으로 자동 보정) vs 경고

**결정: 자동 필렛 기본 제안, 실패 잔여는 경고.** 곡률은 **자동 보정 가능한 유일한 하드 규칙**.

- 이산 곡률(균일 간격 → 3점 원주율 Menger 공식): `R_i = (|AB|·|BC|·|CA|) / (4·Area(A,B,C))`, A=points[i-k], B=points[i], C=points[i+k].
  - **k는 ~15px 상당(≈2 ~ 3점) span** → 픽셀 노이즈 억제(단일 인접점은 지터 취약).
- `R_i < MIN_RADIUS` 정점 → **반경 MIN_RADIUS 원호(필렛)로 치환** 제안. "자동 수정" 누르면 해당 코너만 둥글림(별 꼭짓점 살짝 둥글어짐 — 기존 star_01 꼭짓점도 둥근 bezier: 좌표 [97,-397] 등 참조).
- 필렛으로도 못 살리는(너무 뾰족·자기근접 유발) 코너 → 빨간 하이라이트 + 재편집 요구.

### 6.3 자기근접 — 윈도 추적 한계 반영 (가장 중요한 규칙)

현행 `query()`(architecture §5.3)는 인덱스 한계 윈도(뒤 `RELOCALIZE_BACK_WIN=12` / 앞 `RELOCALIZE_FWD_WIN=40`)로만 재로컬라이즈 → **호길이로 충분히 먼 가지는 절대 다른 가지로 s 순간이동 안 함.** 문제는 **호길이가 애매하게 가까운데(윈도 도달 범위) 공간적으로도 가까운** 두 구간 — 여기서 s가 튀어 피니시/미니맵 깨짐(과거 heart_01·star_01 버그와 동종).

호길이-차(Δs) 3구간 분류:

| Δs 구간 | 의미 | 판정 |
|---|---|---|
| Δs ≤ ARC_EXEMPT(≈110px) | 합법적 급커브(U턴)의 양쪽 — 추적이 인덱스로 자연 분리 | **면제** (곡률 규칙이 별도로 관장) |
| ARC_EXEMPT < Δs ≤ RELOCALIZE_REACH(≈300px) | **크로스락 위험대**: 윈도 도달권 안에서 공간적으로 가까우면 s 점프 가능 | 공간거리 < fail → **하드 리젝트** |
| Δs > RELOCALIZE_REACH | 인덱스 한계가 완전 보호(추적 안전). 단 코리도가 시각적으로 겹칠 수 있음 | 공간거리 < 1.5·fail → **소프트 경고**(플레이어 혼란만) |

```gdscript
# 공간 해시 그리드(셀=fail)로 근접쌍만 검사 → 사실상 O(n)
func check_self_proximity(pts, s_arr, fail) -> Array:
    var violations := []
    var grid := _build_spatial_hash(pts, fail)      # 셀 크기 = fail
    for i in range(pts.size()):
        for j in grid.neighbors(i, fail * 1.5):     # 반경 1.5·fail 후보만
            if j <= i: continue
            var ds := absf(s_arr[i] - s_arr[j])
            if ds <= ARC_EXEMPT: continue           # 합법 급커브 이웃 면제
            var d := pts[i].distance_to(pts[j])
            if ds <= RELOCALIZE_REACH and d < fail:
                violations.append({"i": i, "j": j, "kind": "hard"})
            elif d < fail * 1.5:
                violations.append({"i": i, "j": j, "kind": "soft"})
    return violations
```

> **왜 시작/끝 근접(heart_01 55 ~ 103px)은 통과하나:** 시작·끝 Δs = 전체 길이(~3000px) ≫ RELOCALIZE_REACH → "소프트 경고"에도 fail 거리 조건만 볼 뿐, 애초에 추적 안전. heart·star류 open 루프는 하드 리젝트에 안 걸림.

### 6.4 트랙 길이와 길이 조절

- 재샘플한 뒤 `length`를 계산합니다. 권장 범위(2500~4500) 밖이면 권장 경고로 표시하고, 허용 범위(1500~8000) 밖이면 저장할 수 없습니다.
- 길이는 사용자가 "트랙 길이 조절…"(§4.7)에서 목표를 입력하고 적용했을 때만 바뀝니다. 에디터가 목표 길이를 자동으로 강제하지 않습니다.
- 균일 스케일을 하면 곡률반경도 같은 배율로 바뀝니다. 작게 그린 뾰족한 그림을 키우면 최소반경 규칙을 통과하기 쉬워지고, 반대로 줄이면 곡률·자기근접 위반이 생길 수 있으므로 대화상자가 적용 전에 예상 검증 결과를 보여 줍니다.

### 6.5 시작·끝 & 열림/닫힘

- **열린 경로**: 그린 그대로. 시작=첫 점, 피니시=끝 점. 자동 전진 방향=시작 접선.
- **닫힌 윤곽**(루프 닫기 on): §9 open-루프 저작. 검증상 시작/끝 s-분리 자동 보장.

### 6.6 검증 실패 UX

- 하드 위반이 있으면 저장·테스트 버튼을 비활성화하고, 캔버스 마커와 IssuePanel 목록(§4.4)으로 항목별 사유와 해결 힌트를 보여 줍니다. 위치가 있는 항목은 "위치로"로 카메라를 옮겨 강조합니다.
- 급한 곡선이 있으면 "자동 수정…"이 활성화되며, 미리보기를 확인한 뒤에만 적용합니다(§4.7).
- 권장 경고만 남으면 저장할 수 있습니다. IssuePanel 제목은 "저장 가능"과 권장 경고 수를 표시합니다.
- 검증기 메시지는 길이와 반경을 단위 표기 없이 월드 단위로 적어, 에디터의 "트랙 길이" 표기와 맞춥니다. 판정 기준과 수치는 바꾸지 않았습니다.

## 7. 저장 / 불러오기 / id / 삭제

### 7.1 id 체계 (충돌 방지)

- **`track_id = "custom_" + 8자리 hex`** — 최초 저장 시 1회 생성(랜덤; 예: `"%08x" % (randi())` 또는 시간+랜덤 해시), JSON에 박제. **파일명 = id** → `user://tracks/custom/custom_ab12cd34.json`.
- **랜덤 id(콘텐츠 해시 아님) 이유**: 편집해도 id 불변 → `RecordStore`의 `"id|difficulty"` 기록 유지(콘텐츠 해시는 편집마다 기록 고아화).
- 별도 `checksum`(경로 좌표 SHA-256) 병기: import 중복 감지 + 후속 서버 체크섬 대비.
- 공식 id(`cotton_01`…)와 `custom_` 접두로 **네임스페이스 완전 분리** → 레코드 키·로드 경로 충돌 없음.

### 7.2 저장 경로 & 디렉토리

- 루트: `user://tracks/custom/`. **첫 저장 전 `DirAccess.make_dir_recursive_absolute("user://tracks/custom")` 필수**(없으면 열기 실패 — 함정).
- 파일 = 확장 포맷(§2.3) JSON.

### 7.3 TrackLoader 확장 (수정 — 기존 최소 변경)

`TrackLoader`가 트랙 IO 단일 소유자 → 커스텀 IO도 여기 흡수(새 오토로드 미추가).

```gdscript
const CUSTOM_DIR := "user://tracks/custom/"

# 로드: 공식 우선, custom_ 접두거나 공식에 없으면 user:// 조회
func load_track(track_id: String) -> TrackData:
    if _cache.has(track_id): return _cache[track_id]
    var path := (CUSTOM_DIR + track_id + ".json") if track_id.begins_with("custom_") \
                else (OFFICIAL_DIR + track_id + ".json")
    var data := _load_from_file(path)          # 기존 파서 재사용(폴리라인 bake는 §2.4)
    if data != null: _cache[track_id] = data
    return data

# 목록: user://tracks/custom/ 디렉토리 스캔(웹 IDBFS 포함 안정)
func list_custom_tracks() -> Array:
    var out := []
    var dir := DirAccess.open(CUSTOM_DIR)
    if dir == null: return out
    for f in dir.get_files():
        if not f.ends_with(".json"): continue
        var hdr := _read_header(CUSTOM_DIR + f)   # track_id/name/difficulty만 파싱
        if hdr != null: out.append(hdr)
    out.sort_custom(func(a, b): return a["name"] < b["name"])
    return out

# 저장/삭제
func save_custom_track(track_dict: Dictionary) -> String   # id 반환, 파일 기록
func delete_custom_track(track_id: String) -> bool         # 파일 삭제 + 캐시 무효화
```

> **매니페스트 불필요.** `TrackLoader` 주석이 경계한 것은 **`res://` 패킹 빌드에서 DirAccess 불안정**. `user://`는 데스크톱·웹(IDBFS) 모두 `get_files()` 동작 → 커스텀은 디렉토리 스캔이 정석.

### 7.4 레코드 · 재봉 평점 호환

- `RecordStore`는 `"track_id|difficulty"` 키(custom id 고유) → **무변경으로 커스텀 기록 저장/조회**.
- `RunStats.finalize`의 재봉 평점(`grade`/`grade_score`)은 run 통계 + `track.safe`만 사용 → 커스텀도 동일 → **무변경**.
- 삭제 시 옵션: `RecordStore.purge(track_id)`(신규, 선택)로 고아 기록 정리. 안 지워도 무해(키 고유·미참조).

### 7.5 메뉴 통합 (트랙 선택 화면)

- 커스텀 트랙은 트랙 선택 화면의 유저 트랙 모드에 나타납니다(§14). 이 모드에서 "트랙 만들기"는 새 트랙으로 에디터를 열고, 커스텀 트랙을 고른 뒤 누르는 "편집"은 `GameState.open_editor(id)`로 그 트랙을 엽니다. 저장하면 같은 파일에 기록됩니다.
- 불러오기·내보내기·삭제 버튼도 유저 트랙 모드에만 나타납니다. 공식 트랙 모드에서는 편집 버튼을 표시하지 않습니다.
- 미리보기(`_on_preview_draw`)는 `track.points`만 사용하므로 커스텀 트랙도 실루엣으로 표시됩니다.

## 8. 외부 파일 불러오기 / 내보내기

유저끼리 트랙 JSON을 채팅(Mattermost 등)으로 교환하는 시나리오를 데스크톱·웹 모두 지원.

### 8.1 공용 임포트 파이프라인

데스크톱 파일 경로·웹 업로드가 **같은 텍스트 기반 함수**로 수렴.

```gdscript
# TrackLoader.import_custom_from_text(text, suggested_name) -> Dictionary
#   흐름: 크기 상한(1MB) → JSON 파싱 → 폴리라인 베이크 → TrackValidator 검증 →
#         폴리라인 정규화 + 로컬 새 custom id → user:// 저장(중복이면 스킵)
#   반환: {ok, status, track_id, name, message}
#   status: ok | duplicate | too_large | parse_error | empty_path | validation_error | save_failed
```

- import 시 **반드시 `TrackValidator` 통과**(외부 파일이 추적 불가 기하일 수 있음) 후 저장. 실패 시 거부 + 사유 표시(검증 실패 첫 사유 — 최소반경/자기근접 등).
- 베이크하기 전에 경로 형식을 먼저 검사합니다. 세그먼트는 64개, 점(bezier는 제어점)은 4096개, 좌표 절댓값은 16384까지 받고, 점 사이 원시 길이(bezier는 제어 다각형 길이)가 16000을 넘거나 타입이 틀리면 베이크 없이 거부합니다.
- 불러오기는 `items`, 사용자 지정 `width`, `closed`를 보존합니다. 폭과 아이템 형식이 허브 제약(폭 순서, 아이템 최대 128개, type, s 범위, |lat| ≤ fail)을 어기면 거부합니다. 비어 있지 않은 `modifiers`는 게임이 쓰지 않고 서버도 받지 않으므로 제외하고 가져오며, 결과 메시지에 제외한 개수를 적습니다.
- id는 원본을 유지하지 않고 **로컬 새 id를 부여**합니다(타인의 `custom_xxxx`와 충돌 방지). 중복 판정은 경로만 보지 않고, 플레이 내용 전체(난이도·재질·폭·경로·아이템)의 지문이 같은 트랙이 이미 있을 때만 "이미 있는 트랙"으로 처리합니다. 이때 가져오는 파일과 기존 파일 양쪽에 같은 정규화(베이크 → 0.1 격자 조밀 점 열)를 적용한 뒤 지문을 비교하므로(`import_fingerprint`), 예전 버전이 저장한 파일을 다시 가져와도 같은 트랙으로 판정합니다. 허브 다운로드 매핑이 쓰는 원본 지문(`custom_track_fingerprint`)은 이 규칙과 별개입니다. 경로가 같아도 폭·재질·아이템이 다르면 새 트랙으로 저장합니다.
- **크기 상한 1MB**(`IMPORT_MAX_BYTES`)로 대용량·악의적 입력 방어.

### 8.2 플랫폼별 진입

| 플랫폼 | 불러오기 | 내보내기 |
|---|---|---|
| 데스크톱 | **`FileDialog`(열기)** + **드래그앤드롭**(`get_window().files_dropped`) → 파일 텍스트 → 공용 파이프라인 | **`FileDialog`(저장)** → 커스텀 트랙 JSON 원본을 선택 경로에 복사 |
| 웹 | **`WebFileBridge.pick_file`**: `JavaScriptBridge`로 `<input type=file accept=".json">` 생성 → `FileReader.readAsText` → GDScript 콜백 → 공용 파이프라인 | **`WebFileBridge.download_text`**: 내장 `JavaScriptBridge.download_buffer`(Blob + `<a download>`)로 다운로드 |

- 웹 브리지 헬퍼 `scripts/ui/WebFileBridge.gd`(`RefCounted`, 오토로드 아님 — 화면이 멤버로 보관). `create_callback`로 만든 `JavaScriptObject`를 **멤버로 붙잡아 둠**(GC로 콜백 사망 함정 방지).
- 내보내기 파일명 `<트랙명 sanitize>_<id>.json`. 진입점: **TrackSelect에서 커스텀 트랙 선택 시 "내보내기" 버튼**(공식 트랙은 저장소에 있으니 숨김). 불러오기는 TrackSelect·TrackEditor 양쪽에 있습니다. TrackEditor에서 불러오면 저장하지 않고 편집 문서로 올리며, 기하 검증에 실패하는 파일도 고쳐 쓸 수 있도록 엽니다. 불러오기에 실패하면 기존 문서·id·화면은 바뀌지 않고, 저장하지 않은 변경이 있으면 교체하기 전에 확인하며, 불러오기 자체도 실행취소 한 단계입니다.
- 성공/실패는 토스트(TrackSelect)·StatusLabel(TrackEditor)로 알림. 가져온 트랙은 목록에 즉시 등장 + 선택 상태.

## 9. 닫힌 윤곽을 open path로 저작 (핵심 함정)

하트·별처럼 "닫힌 것처럼 보이는" 트랙도 **경로는 선형(open)** 필수. 이유:

- 피니시 판정 = `probe.s >= track.length − 1.0`(RaceDirector.gd:164). 경로가 literally 닫히면(끝=시작 좌표 동일) 끝 지점 s가 시작과 붙어 **피니시가 영영 안 오거나** 시작/끝 최근접 혼동.
- 기존 `heart_01`이 정답 패턴: 시작 `[-227,313]`, 끝 `[-162,393]` — **가깝지만 다른 점**, 그 사이 작은 갭. 시작(초록)·피니시(체크) 마커가 이 갭에 위치.

**`_apply_close_gap` 규칙:**
- "루프 닫기" 켜면 끝점을 시작점으로 **완전 연결 안 하고** 시작점 근처(예: 시작 접선 방향으로 `fail` ~ `1.5·fail` 못 미친 지점)에서 끊음.
- 시작/끝 Δs = 전체 길이 유지(§6.3 하드 리젝트 면제 보장).
- 시각적으로 거의 닫힌 하트/별, 기능적으로 s 단조 증가 open 트랙.

```gdscript
func _apply_close_gap(r: PackedVector2Array) -> PackedVector2Array:
    # 끝을 시작 근처로 당기되, 시작점과 GAP(=fail) 만큼 간격을 남긴다.
    var start := r[0]
    var gap := 90.0
    # 시작 접선 반대쪽으로 gap 떨어진 지점까지만 이어지도록 끝 구간을 트림/보간.
    return _trim_end_to_gap(r, start, gap)
```

## 12. 구현 순서 · 규모 · 함정

### 12.1 권장 순서

1. `TrackData._bake_polyline` + `TrackLoader` custom load/list (백엔드부터 — 손으로 만든 polyline JSON을 넣어 플레이 검증 가능).
2. `TrackValidator`(곡률·길이·자기근접) — 단위 테스트 대상(순수 함수).
3. `StrokeProcessor`(평활·재샘플·닫기).
4. `DrawCanvas`(그리기·미리보기·마커) → `TrackEditor`(모드·언두·저장).
5. `MainMenu` 통합(Custom 섹션·진입·삭제).
6. import(데스크톱 다이얼로그+드래그드롭).
7. (후속) 웹 import, polyline→bezier canonical 변환기, 커뮤니티 공유/서버.

### 12.2 규모 추정

- **신규 5 파일 + 수정 4 파일.**
- **난이도: 중.** 순수 로직(bake·validator·processor)은 자명·테스트 가능. 실질 난도는 `DrawCanvas` 마우스 UX(pan/zoom·모드·마커)·`MainMenu` 통합에 집중.
- 대략 **4 ~ 5 개발일**(백엔드 1.5 + 에디터 UI 2 + 통합/삭제/import 1). 웹 import 별도.

### 12.3 구현 워커가 주의할 함정

1. **자기근접 = 최우선 함정.** 검증 느슨하면 그린 트랙에서 과거 heart/star의 s 순간이동·피니시 미발동 버그 재현. §6.3 Δs 3단 분류(면제/하드/소프트) 반드시 준수. 임계(ARC_EXEMPT·RELOCALIZE_REACH)는 추적 윈도 상수에서 유도된 값.
2. **닫힌 루프는 open으로 저작(§9).** 끝=시작 좌표로 literally 닫으면 피니시 깨짐. heart_01의 "작은 갭" 패턴 재현.
3. **polyline은 반드시 ≤6px 재샘플(§2.4).** query의 인덱스 윈도가 6px 간격 전제. 성긴 폴리라인은 추적 거동 변화.
4. **id 네임스페이스·파일명=id.** `custom_` 접두 필수, 공식 로드가 커스텀을 가리지 않게 로드 경로를 접두로 분기.
5. **곡률은 평활 후 스텐실(±~15px)로 측정.** 인접 3점 생값으로 재면 손떨림에 모든 트랙 곡률 실패.
6. **user:// 디렉토리 선행 생성**(`make_dir_recursive`) — 첫 저장 함정.
7. **좌표는 월드 단위로 저장, 그릴 때만 변환.** 화면 좌표로 저장하면 pan/zoom·해상도 종속. 큰 트랙(±500px+) 위해 pan/zoom 필수.
8. **커스텀은 리더보드 제외.** `is_custom`를 결과 dict까지 전달 → (후속)LeaderboardClient가 온라인 제출 스킵. 로컬 기록만.
9. **웹 FileDialog 부재.** 데스크톱 네이티브 다이얼로그/드래그드롭이 웹에 없음 → 웹 import는 JS 브리지/붙여넣기로 분리(후속).
10. **시작 heading·피니시 라인은 첫/끝 두 점에 의존.** 퇴화(모든 점 동일·2점 미만) 폴리라인을 검증에서 하드 리젝트(최소 점 수·유효 길이).
11. **코너가 6px 재샘플에 묻힘.** 별 꼭짓점 같은 급전환점을 코너 후보로 표시해 재샘플 시 강제 삽입하지 않으면 의도한 뾰족함이 사라짐(§5-0/1). 저장 전 정규화(중복점 제거·quantize·상한)도 함께.
12. **`closed`를 판정에 쓰지 말 것.** 스키마 `closed`는 에디터 재편집 힌트일 뿐, `bake()`/`query()`는 무시. `closed=true`로 끝→시작 이으면 피니시 깨짐(§2.3, §9).

## 14. 공유 허브 사용법

공유 허브는 내가 만든 커스텀 트랙을 공개하고, 다른 사람이 올린 트랙을 찾아 내려받는 기능입니다. 계정은 필요하지 않습니다. 서버 API와 업로드 제한은 `server/README.md`의 "커스텀 트랙 공유 허브 API" 절에 정리되어 있습니다.

메인 화면에서 Start를 누르면 "공식 트랙"과 "유저 트랙" 가운데 하나를 고르는 화면이 먼저 나타납니다. "유저 트랙"을 고르면 트랙 선택 화면이 유저 트랙 모드로 열리고, 목록에는 직접 만든 트랙과 허브에서 받은 트랙만 나타납니다. 공유 허브에는 이 모드에서 Play 버튼 옆의 "공유 허브" 버튼이나 트랙별 "허브에 게시" 버튼으로 들어갑니다. 유저 트랙이 하나도 없으면 목록 대신 안내 문구가 나타나고, "공유 허브" 버튼에 포커스가 놓입니다. 허브 화면에서 뒤로 나오면 트랙 선택 화면의 유저 트랙 모드로 돌아갑니다. "공식 트랙"을 고르면 공식 트랙만 목록에 나타나며, 트랙 만들기·불러오기·내보내기·삭제·허브에 게시·공유 허브 버튼은 표시되지 않습니다.

### 14.1 게시

1. 유저 트랙 모드의 트랙 선택 화면에서 게시할 로컬 커스텀 트랙을 고른 뒤 "허브에 게시"를 누릅니다. 저장본이 로드와 검증(§6)을 통과해야 게시 화면으로 넘어갑니다.
2. 제목(1~80자), 작성자 표시명(1~32자), 설명(선택, 최대 1000자)을 확인합니다. 제목은 트랙 이름으로, 작성자 표시명은 설정된 닉네임으로 미리 채워집니다.
3. "게시하기"를 누르면 공개 게시 안내가 나타납니다. 게시한 트랙과 입력한 문구는 누구나 볼 수 있고, 게시한 뒤에는 수정할 수 없습니다. 고친 트랙은 새 게시물로 올리고 이전 게시물은 삭제하면 됩니다.

공식 트랙에는 게시 버튼이 나타나지 않습니다. 허브에서 내려받은 트랙도 그대로는 다시 게시할 수 없으며, 에디터에서 편집해 내용이 달라진 사본만 새 게시물로 올릴 수 있습니다. 작성자 표시명은 게시자가 직접 입력한 이름이므로, 화면은 이 이름을 인증된 신원처럼 표시하지 않습니다.

### 14.2 찾기와 내려받기

허브 목록은 최신순으로 20개씩 보여 주며, "더 보기"를 누르면 다음 20개를 이어서 불러옵니다. 검색 칸에 제목의 일부(최대 80자)를 입력하면 제목이 부분적으로 일치하는 게시물만 보여 줍니다. 게시물을 고르면 상세 화면에서 경로 미리보기, 작성자 표시명, 설명, 난이도, 재질, 길이, 등록일을 확인할 수 있습니다.

"다운로드"를 누르면 트랙이 새 `custom_` id를 가진 로컬 커스텀 트랙으로 저장되고, "다운로드 후 플레이"를 누르면 저장한 뒤 곧바로 주행을 시작합니다. 저장한 트랙은 네트워크 없이도 다른 커스텀 트랙처럼 플레이할 수 있습니다. 유저 트랙 목록에서는 허브에서 받은 트랙의 정보 줄에 "허브" 표식이 붙기 때문에, "CUSTOM" 표식이 붙은 직접 만든 트랙과 구분할 수 있습니다. 같은 게시물을 다시 내려받으면, 로컬 사본이 남아 있고 내용이 그대로일 때 새 파일을 만들지 않고 기존 트랙을 사용합니다. 로컬 사본을 지웠거나 편집했다면 새로 저장합니다. 저장에 실패하면 플레이를 시작하지 않고 실패 사유를 보여 줍니다.

허브에서 받은 JSON을 파일로 저장해 유저 트랙 모드의 "불러오기"(§8)로 들여오면 허브 다운로드와 다른 규칙이 적용됩니다. 불러오기도 아이템, 사용자 지정 폭, closed를 보존하지만, 경로를 6 간격으로 다시 베이크해 저장하고 게시물 매핑을 남기지 않습니다. 중복 판정은 플레이 내용 전체의 지문으로 하므로, 경로가 같아도 폭·재질·아이템이 다르면 새 트랙으로 저장합니다. 같은 게시물을 다시 받았을 때 기존 트랙을 재사용하려면 허브의 "다운로드"를 사용해야 합니다.

### 14.3 삭제 토큰 보관

게시에 성공하면 서버가 삭제 토큰을 한 번만 돌려주고, 게임은 이 토큰을 `user://community/published.json`에 보관합니다. 토큰은 트랙 JSON, 내보내기 파일, 게시 요청 본문에는 들어가지 않습니다. 토큰을 보관한 기기에서만 상세 화면에 "게시물 삭제" 버튼이 나타나며, 확인 단계를 거친 뒤 삭제합니다.

토큰은 이 기기에만 저장되므로, 브라우저 데이터나 앱 데이터를 지우면 그 게시물을 삭제할 권한을 잃게 됩니다. 토큰을 저장하지 못한 경우에는 게시 완료 화면이 토큰을 그대로 보여 주므로, "토큰 복사"로 복사해 따로 보관해야 합니다. 이때 업로드는 이미 성공했으므로 다시 게시하지 않습니다. 업로드가 진행되는 동안에는 게시 화면을 떠날 수 없습니다. 저장하지 못한 토큰은 게임을 종료하기 전까지 메모리에 남아 있어서, 허브에 다시 들어오면 같은 안내가 다시 나타납니다. "다시 저장"에 성공하거나 "보관했습니다"를 누르면 이 안내는 더 이상 나타나지 않습니다.

### 14.4 기록

허브에서 받은 트랙은 로컬 커스텀 트랙과 똑같이 기록을 이 기기에만 저장하며, 공식 리더보드에는 제출하지 않습니다. 상세 화면과 결과 화면에도 같은 안내가 표시됩니다. 게시물 매핑은 `user://community/downloads.json`에 저장되며, 이 파일이 손상되면 게임은 파일을 무시하고 다음 다운로드 때 새로 만듭니다. 이때 손상된 파일은 덮어쓰지 않고 `.bak` 접미사를 붙여 보존하며, `published.json`에도 같은 규칙을 적용합니다.
