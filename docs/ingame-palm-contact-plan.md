# 인게임 손 밀착 자세와 바늘 연출 개선 계획

이 작업은 `docs/concepts/ingame-palm-contact-v1.png`의 메인 장면을 실제 게임의 표현 계층에 적용합니다. 컨셉 하단의 바늘 비교 컷은 애니메이션 설명용이므로 게임 화면에 추가하지 않습니다. 기본 캐릭터와 엄마 캐릭터, 부상과 골무 상태에서 손 자세가 일관되어야 합니다.

## 1. 현재 구조와 수정 이유

| 위치 | 현재 동작 | 필요한 변경 |
|---|---|---|
| `game/scenes/Gameplay.tscn` | 양손이 `(175,276)`, `(1105,276)`에 1.2배로 배치됩니다. | 새 손의 낮은 손목과 눕힌 손바닥이 원단에 놓이도록 위치와 표시 크기를 조정합니다. |
| `HandView.gd::_draw_hand_tex()` | 원본 텍스처 크기로 그리며, `mirror`로 좌우를 반전합니다. | 공통 표시 사각형으로 고해상도 이미지를 그립니다. 모든 변형에 같은 사각형과 원점을 사용합니다. |
| `HandView.gd::_draw()` | 조향 시 확대 7%, 안쪽 16px, 아래 12px를 적용하고 드리프트 시 더 증폭합니다. | 손목이 들뜨지 않도록 확대와 세로 움직임을 줄이고, 접촉 그림자가 손과 함께 이동하게 합니다. |
| `PresentationController.gd` | 부상 3단계와 골무 변형을 선택하고 엄마 얼굴·손을 0.35초 동안 전환합니다. | 새 에셋 경로로 교체하되 상태 전환과 복원 구조를 유지합니다. |
| `NeedleView.gd` | 26px 왕복하고, 바늘을 먼저 그린 뒤 노루발로 덮습니다. 속도 0에서도 위상이 진행됩니다. | 노루발을 확대하고, 별도 바늘대를 노출하며, 관통점을 기준으로 큰 상하 운동을 구현합니다. |
| `PresentationController.gd::_place_needle()` | `v_needle() = 0.42 + 28/140 = 0.62` 위치를 사용합니다. | 이 투영 기준은 유지하고 이미지의 슬롯과 바늘 끝을 기준점에 맞춥니다. |
| `TutorialDialog.gd::_needle_rect()` | 160×160 고정 사각형으로 노루발 주변을 강조합니다. | 커진 노루발을 포함하도록 콜아웃 범위를 수정합니다. |

모든 경로에서 위 파일명은 `game/scripts/presentation/` 기준이며, `TutorialDialog.gd`만 `game/scripts/ui/`에 있습니다. 물리·조향 판정·점수·트랙·서버 코드는 변경하지 않습니다.

에셋은 내장 `image_gen`으로 생성하여 `game/assets/gfx/palm_contact/`에 저장합니다. 기존 PNG를 덮어쓰지 않고 새 경로를 연결합니다. 기준 손은 화면 오른쪽에 표시하는 방향이며, 왼쪽 손은 기존 `mirror=true`를 사용합니다.

| `handcut1_flat.png` | 첫 번째 부상: 오른손 검지 밴드 |

현재 기본 부상 배열에서 사용하지 않는 `handcut4.png`는 그대로 둡니다. 엄마 얼굴은 기존 `face_mom.png`를 재사용합니다. 엄마 손 위에 플레이어의 부상이나 골무를 합성하지 않습니다. 엄마 찬스가 끝나면 이전 플레이어 상태로 돌아가는 기존 우선순위를 유지합니다.

바늘 끝은 기존 `needle.png`를 재사용하고 긴 바늘대는 기존 금속 색상을 사용한 사각형과 하이라이트로 그립니다. 이 형태는 새로운 대형 PNG 없이 만들 수 있습니다. 바늘과 바늘대는 함께 움직이고 노루발은 움직이지 않습니다.

## 3. 구현 순서와 표시 기준

### 3.1 손과 상태 전환

1. 새 손 9종을 같은 표시 사각형에 그립니다. 원본은 1448×1086이며, 기존 `draw_texture()`를 그대로 사용하면 손이 지나치게 커집니다. `draw_texture_rect()`와 공통 크기를 사용합니다. 텍스처마다 불투명 영역으로 자동 크롭하면 상태 전환 시 손 위치가 달라지므로 하지 않습니다.
2. 1280×720에서 시작값은 표시 크기 약 640×360, 중심 좌표 약 `(210,400)`과 `(1070,400)`, 씬 스케일 1.0입니다. 세로 압축은 낮은 카메라의 원근감을 위한 시작값입니다. 실제 렌더를 보고 해부학적 형태가 부자연스럽게 찌그러지지 않는 범위에서 조절합니다. 값 자체보다 손목과 손바닥의 접촉, 중앙 재봉선의 가시성을 우선합니다.
3. 손목 아래와 손바닥·손가락 아래에 짧고 밀착된 접촉 그림자를 그립니다. 별도 큰 원형 그림자는 사용하지 않습니다. 손 이미지와 같은 변환 및 엄마 전환 오프셋을 적용해 손만 빠져나간 자리에 그림자가 남지 않게 합니다.
4. `PRESS_SCALE`은 약 0.01~0.02, `PRESS_DOWN`은 2~3px, `PRESS_INWARD`는 8~12px부터 조절합니다. 세로 진동은 0.5px 이하를 시작값으로 합니다. 최대 조향과 드리프트에서도 손이 원단에서 들뜨거나 노루발을 덮지 않아야 합니다.
5. `_base_texture`, `_cut_texture`, `_thimble_on`, `_mom_swipe`의 책임과 `reset_hands()` 동작을 유지합니다. 기존 API를 재사용하고 새로운 캐릭터 상태 시스템은 만들지 않습니다.

### 3.2 노루발과 바늘

1. 노루발의 실제 불투명 폭이 기존보다 약 1.7배가 되도록 그립니다. 투명 여백을 포함한 PNG 크기만 비교하지 않습니다. 새 이미지를 폭 약 220~250px로 표시한 뒤 슬롯과 관통점을 정렬합니다.
2. `NeedleView`의 원점 `(0,0)`은 내려간 바늘의 관통점으로 유지합니다. 원점은 `PresentationController.v_needle()`과 일치해야 합니다. 이미지를 확대할 때 슬롯 위치가 함께 내려가지 않도록 `foot_rect`의 오프셋을 명시합니다. 바늘 최하단은 원점에 맞추고 원단 아래로 길게 돌출하지 않게 합니다.
3. 바늘의 상승점은 원점보다 80~100px 위를 시작값으로 정합니다. 노루발 앞면에 가려 왕복이 보이지 않는 기존 그리기 순서를 재검토합니다. 얇은 바늘대와 바늘 끝이 보이되, 노루발의 양쪽 발을 부자연스럽게 관통하는 것처럼 그리지 않습니다.
4. 바늘대는 화면 상단 방향으로 길게 이어지고 바늘과 같은 이동량을 사용합니다. 얼굴 중앙을 넓게 가리는 굵은 기둥은 피합니다. 슬롯 사이로 원단과 재봉선이 보여야 합니다.
5. 왕복은 `delta` 기반 위상을 사용합니다. 속도에 비례하되 최고속에서도 왕복이 읽히도록 약 3~7Hz 범위부터 조절합니다. 정지·카운트다운·완주 시에는 기존 `running` 판정 등 표현 계층의 정보를 활용해 상승 위치로 부드럽게 멈춥니다. 정지할 때 위상을 갑자기 초기화해 바늘이 순간 이동하지 않게 합니다. 일시정지는 기존 프로세스 모드를 따릅니다.
6. `set_speed()`의 모든 호출자는 `PresentationController`에 있습니다. 주행 상태 인자를 추가한다면 그 호출을 함께 변경하고, 이미 계산하는 이동 히스테리시스를 재사용합니다. 렌더 프레임마다 이동량이 0인 것만으로 바늘을 멈추면 90/120Hz에서 흔들리므로 피합니다.
7. 튜토리얼 강조 영역은 확대된 노루발을 감싸되 긴 바늘대 전체를 감싸 화면을 덮지 않도록 조절합니다.

### 3.3 리소스와 문서

- 새 PNG의 투명도를 유지하고, Godot import의 `process/fix_alpha_border=true`를 사용합니다. 새 경로에 기존 UID를 복사하지 않습니다.
- 고해상도 소스는 보존하되 손 텍스처는 import 크기 제한 768px 정도, 노루발은 512px 정도부터 검토합니다. 각 손 변형에 같은 제한을 적용합니다. 실제 표시 크기와 모바일 메모리를 확인한 뒤 확정합니다.
- 기존 HUD와 터치 조작 영역, 1280×720 기준 및 레터박스를 유지합니다. 이 작업을 위해 원단 셰이더의 투영값이나 모바일 DPR 정책을 바꾸지 않습니다.
- `game/assets/gfx/README.md`에 새 에셋과 상태 매핑을 추가하고 `docs/presentation.md`에 최종 배치와 바늘 기준점을 기록합니다. `docs/mobile.md`는 이 작업과 무관한 계획을 수정하지 않습니다.

## 4. 검증과 완료 조건

Godot 4.6.1 실행 파일은 이 환경의 `/Users/bnbong/Downloads/Godot.app/Contents/MacOS/Godot`에 있습니다. 별도로 설치된 `Godot 2.app`는 4.7이므로 검증 엔진을 혼동하지 않습니다. 실제 사용자 기록이 오염되지 않도록 런타임 검증은 격리된 프로젝트 사본이나 별도의 user data 설정에서 실행합니다.

1. 새 PNG 10개를 검사합니다. 모든 손은 같은 크기이며 RGBA 투명 배경을 가져야 합니다. 노루발 슬롯의 중앙도 투명해야 합니다. 손가락은 엄지를 포함해 5개여야 하고, 부상·골무 교체 시 관절과 손끝 위치가 눈에 띄게 움직이지 않아야 합니다.
2. `gdparse`와 `gdlint`로 변경 스크립트를 검사하고, Godot 4.6.1 headless import 및 게임 부팅에서 누락 리소스와 파싱 오류가 없는지 확인합니다.
3. 최소한의 실행 가능한 회귀 검사 하나를 남깁니다. 기본→부상 1/2/3→골무 켜기/끄기→엄마 진입/복귀→리셋의 상태 복원, 바늘 상하 끝점과 고정된 노루발, 정지 동작을 검사합니다. 검사 편의를 위한 별도 범용 프레임워크는 추가하지 않습니다.
4. 1280×720 실제 렌더에서 기본 손, 엄마 손, 부상+골무 조합, 바늘 상승·하강 화면을 저장해 컨셉과 비교합니다. 정적 화면만으로 애니메이션 성공을 단정하지 말고 여러 프레임이나 짧은 녹화로 왕복을 확인합니다.
5. 좌/우 최대 조향과 드리프트에서 중앙 재봉선과 노루발이 가려지지 않는지 확인합니다. 엄마 전환 후 원래 밴드·골무 상태가 복원되고 잔상이나 그림자가 남지 않아야 합니다.
6. 가로 모바일 844×390 및 932×430의 레터박스 화면에서도 HUD와 터치 버튼이 가려지지 않는지 확인합니다. 실제 iOS 검증을 못 했다면 데스크톱 검증과 구분해 보고합니다.
7. 테스트 성공 여부, 실제 캡처 경로, 남은 시각적 차이와 미검증 항목을 기록합니다. 요청받지 않은 배포·push·커밋은 하지 않습니다.

## 5. Claude Fable에 전달할 작업

사용자가 지정한 `~/.claude/CLAUDE.md`의 Fable 오케스트레이션 정책을 따릅니다. Fable은 구현 파일을 직접 수정하지 않고 작업을 배분하고 결과를 검증합니다. 독립적인 작업은 병렬로 시작하고, 같은 파일의 편집은 담당자를 분리하여 충돌을 막습니다.

- `default-worker`(Opus)는 손 렌더링·씬 배치·상태 연결을 담당합니다.
- 다른 `default-worker`(Opus)는 `NeedleView.gd`와 튜토리얼 강조 영역을 담당할 수 있습니다. `PresentationController.gd`와 `Gameplay.tscn`의 편집은 첫 워커 한 명에게 모으고 바늘 워커는 필요한 연결 변경을 전달합니다.
- `task-worker`(Sonnet)는 계약을 확인한 뒤 작은 회귀 검사와 문서를 담당합니다. 한글 문서 작성 전 fluent-korean 원문을 읽게 합니다.
- 구현 후 `codex-reviewer`로 교차 검토하고 Fable이 실제 diff·테스트·렌더 결과를 대조합니다. 워커의 자기 보고만으로 완료 처리하지 않습니다.

오케스트레이션이 작동했다는 근거는 Fable 세션 ID와 실제 사용 모델, 워커 호출 기록 및 ID, 작업 시작 또는 결과 로그입니다. 설정 파일의 존재나 Fable의 수행 예정 문장만으로 실행을 확인했다고 하지 않습니다. 시작 확인과 전체 구현 완료는 구분해서 보고합니다.
