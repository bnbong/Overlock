# 커스텀 트랙 공유 허브와 모바일 조향 버튼 확대 계획

작성일: 2026-09-30. 구현 전 계획이며 아래 신규 수치는 초기 설계값이다.

## 목표와 범위

게임 안에서 자신이 만든 트랙을 공개하고 다른 사람이 검색·미리보기·다운로드해 플레이할 수 있게 한다. 모바일은 인게임 좌우 조향 버튼만 살짝 키운다.

첫 버전은 계정 없는 공개 게시, 제목 검색, 최신순 목록, 상세·경로 미리보기, 로컬 다운로드, 플레이, 게시자 삭제를 제공한다. 닉네임은 작성자가 입력한 표시명이며 인증된 신원으로 표시하지 않는다.
계정·댓글·좋아요·인기순·커뮤니티 리더보드·즐겨찾기·웹 공유 링크 랜딩 페이지는 후속 범위다. 크기 조절 슬라이더, 다른 모바일 버튼 확대, 메뉴 전체 개편도 범위 밖이다.

## 확인한 현재 구조

- Godot 클라이언트와 FastAPI/SQLAlchemy 서버가 있다. 서버의 Track/Run과 /api/tracks, /api/runs, /api/leaderboard는 공식 트랙 기록 체계다.
- TrackLoader는 user://tracks/custom/에 custom_ ID로 저장하고 JSON 가져오기·내보내기, 1MiB 입력 제한, TrackValidator 검사, 경로 체크섬 중복 판정을 제공한다.
- 현재 로컬 체크섬은 경로만 반영한다. 폭·재질·아이템이 다른 같은 경로를 허브에서 동일 트랙으로 잘못 처리하지 않도록 별도 확인이 필요하다.
- TrackSelectScreen에는 커스텀 목록, 생성·삭제·가져오기·내보내기와 플레이 흐름이 있다. 커스텀은 공식 온라인 리더보드 대상이 아니다.
- 서버는 init_db의 create_all로 테이블을 만들고 공식 트랙을 시드한다. 신규 독립 테이블 추가로 기존 기록을 보존할 수 있다.
- 서버 ContentLengthLimitMiddleware는 선언된 Content-Length만 검사한다. 공개 트랙 업로드는 실제 수신 바이트 제한도 필요하다.
- TouchControls.STEER_SIZE=112, SPEED_SIZE=112, DRIFT_SIZE=132, PAUSE_SIZE=80이다. EDGE_MARGIN=16, BUTTON_GAP=16, HIT_PAD=8이다.
- HUD._apply_touch_layout은 STEER_SIZE로 RISK 위치를 계산하고 TutorialDialog는 button_rect로 안내 위치를 계산한다.

## 1. 모바일 조향 버튼

TouchControls.gd의 STEER_SIZE만 112 → 128로 변경한다. 한 변 약 14% 확대다. 기존 왼쪽·아래 여백과 버튼 간격, 오른쪽 속도·DRIFT·일시정지 버튼은 유지한다.
렌더링과 터치 판정은 같은 button_rect를 계속 사용한다. 아이콘 크기가 사각형과 비례하는지 확인하고 필요한 경우 조향 아이콘만 조정한다.

1280×720 기준 예상 사각형:
- 왼쪽: (16, 576, 128, 128)
- 오른쪽: (160, 576, 128, 128)

RISK 및 효과 카드가 16px 위로 따라가는 것은 허용한다. 말풍선·미니맵·튜토리얼과 충돌하지 않는지 확인한다. 겹치면 조향 확대 때문에 필요한 최소 배치만 조정하고 다른 버튼 크기를 바꾸지 않는다.
좌→우 슬라이드, 두 손가락 조향+DRIFT/속도 조절, 버튼 밖 드래그, 터치 취소·일시정지·포커스 상실 후 해제를 보존한다. 키보드 조향과 시뮬레이션은 변경하지 않는다.

## 2. 허브 사용자 흐름

### 게시

로컬 커스텀 트랙 선택 → “공유 허브에 게시” → 제목·작성자 표시명·설명 확인 → 공개 게시 안내 → 업로드 → 상세 화면.
유효한 저장본만 게시한다. 공유 허브에서 다운로드한 트랙을 원본인 것처럼 한 번에 재게시하는 버튼은 제공하지 않는다. 별도로 편집한 로컬 사본은 새 게시물로 취급한다.
게시된 내용은 첫 버전에서 불변이다. 수정본은 새 게시물로 올리고 기존 게시물은 게시자가 삭제할 수 있다. 공식 트랙 게시 버튼은 비활성화한다.

### 찾기와 플레이

트랙 선택 화면에 “공유 허브” 진입 버튼 → 최신순 목록(20개 단위, 최대 50개) → 제목 검색 → 상세 화면 → “다운로드” 또는 “다운로드 후 플레이”.
목록은 제목·작성자 표시명·난이도·재질·등록일만 요청한다. 상세 화면에서 경로를 받아 기존 미리보기 그리기를 재사용한다. 이미지 업로드/서버 렌더링은 추가하지 않는다.
검색은 제목 부분 일치, 최대 80자로 제한하고 SQL 바인딩을 사용한다. 안정적인 created_at + id 정렬과 limit/offset으로 시작한다.
다운로드 완료 후에는 네트워크 없이 기존 로컬 커스텀 트랙처럼 플레이한다. 저장 실패 시 플레이 성공으로 처리하지 않는다.
로딩·빈 목록·검색 결과 없음·통신 실패·429·삭제된 게시물·검증 실패를 구분한다. 화면 이동 후 도착한 응답은 폐기하고 버튼 연타로 중복 업로드하지 않는다.

## 3. 저장 모델과 API

기존 공식 Track/Run을 확장해 혼합하지 않고 community_tracks 테이블 하나를 추가한다.

| 필드 | 용도 |
|---|---|
| id | 서버 발급 UUID, 공개 식별자 |
| title / author_name / description | 최대 80 / 32 / 1000자, 공백 정리, 제어문자 제한 |
| track_json | 서버 검증 후 허용 필드만 담은 JSON |
| content_hash | 서버 정규화한 플레이 데이터 전체의 SHA-256 |
| created_at | UTC 등록 시간 |
| delete_token_hash | 게시자 삭제 권한 검증용 해시 |
| deleted_at | 삭제 시각, 기본 null |

난이도·재질은 검증된 JSON에서 읽거나 목록용 컬럼으로 보관한다. 전체 JSON을 목록 응답에 넣지 않는다. 공식 트랙 ID와 로컬 파일 경로는 서버가 받아 신뢰하지 않는다.

| API | 동작 |
|---|---|
| GET /api/community/tracks?q=&limit=20&offset=0 | 공개 목록, total 포함 |
| GET /api/community/tracks/{id} | 메타데이터와 검증된 트랙 JSON, content_hash |
| POST /api/community/tracks | 게시, 201로 id와 삭제 토큰 1회 반환 |
| DELETE /api/community/tracks/{id} | Bearer 삭제 토큰 검증 후 비공개 처리 |

삭제 토큰은 secrets로 충분한 길이의 난수를 생성하고 서버에는 SHA-256만 저장한다. 비교는 일정 시간 비교 함수를 사용한다. 목록·상세·로그에 토큰/해시를 노출하지 않는다.
클라이언트는 토큰을 별도 user:// 파일에 보관하며 트랙 JSON 내보내기나 게시 payload에 포함하지 않는다. 게시 완료 화면에서 토큰을 로컬에 보관한다는 점과 브라우저 데이터 삭제 시 관리 권한을 잃는다는 점을 안내한다. 저장 실패 시 성공한 게시물의 삭제 토큰을 복사할 수 있도록 유지하고 업로드를 자동 재시도하지 않는다.
별도 로그인이나 소유자 수정 API는 만들지 않는다. 토큰 없는 타인은 삭제할 수 없어야 한다. 운영자에게는 서버에서 실행하는 최소 비공개 처리 명령을 제공한다. 공개 관리자 API는 만들지 않는다.

## 4. 업로드 검증과 부하 제한

클라이언트의 TrackValidator 성공만으로 서버 검증을 대체하지 않는다. 현재 저장·베이크 포맷을 확인한 뒤 업로드는 정규화된 폴리라인으로 제한한다.
서버는 허용된 path·폭·난이도·재질·아이템 등 실제 플레이 필드만 보관하고, 클라이언트 length/checksum/is_custom/id는 재계산하거나 제거한다.

초기 제한:
- 메타데이터를 포함한 실제 HTTP 본문 1MiB. Content-Length 누락·거짓·chunked에서도 초과 수신 즉시 413. 기존 작은 기록 제출 제한을 무작정 전체 상향하지 않는다.
- 정규화 점 최대 4096개, 좌표는 유한수 및 절댓값 100000 이내. bool/string을 숫자로 묵시 변환하지 않는다.
- 최소 점 수·길이·곡률·자기근접은 현재 TrackValidator의 하드 거부 기준과 맞춘다. soft 경고는 허용한다.
- 폭은 유한 양수이고 perfect < safe < fail, 각 값 최대 1000. 난이도·재질은 현재 지원 목록만 허용한다.
- 아이템 최대 128개, 타입은 현재 지원값만, 위치·측면값은 유한수 및 현재 트랙의 유효 범위. 미지원 editor_version/필드 타입은 명시적으로 거부한다.
- 게시 IP당 분당 3회, 일일 30회; 조회 IP당 분당 120회 초기값. 기존 신뢰 프록시 IP 추출을 재사용하되 기록 제출과 별도 버킷을 쓴다.

위 상한은 기존 에디터가 만드는 실제 표본을 먼저 비교하고 정상 트랙을 배제하면 근거와 함께 조정한다. 복잡도 큰 기하 검사는 개수/본문 제한 뒤에 수행한다. Python/Godot 공통 fixture로 같은 입력의 수락·거부 및 경로 길이를 비교한다.
닉네임·설명은 일반 텍스트로 그려 BBCode·HTML·외부 이미지 URL을 해석하지 않는다. 원격 리소스/스크립트 실행과 임의 경로 저장은 허용하지 않는다.
기존 RateLimiter가 프로세스 메모리 기반이라면 단일 워커 한계를 문서화한다. 공개 운영에서 다중 워커를 쓰는 경우 프록시 공통 제한 또는 기존 DB 기반 제한으로 맞추고 새 Redis 의존성은 도입하지 않는다.

## 5. 로컬 가져오기와 기록 분리

기존 TrackLoader의 검증·정규화·저장 흐름을 재사용한다. 서버 JSON을 경로에 직접 기록하는 우회 구현은 하지 않는다.
공유 게시물 id → 로컬 custom_ id + 서버 content_hash 매핑을 별도 로컬 manifest로 보관한다. 삭제된 로컬 파일의 매핑은 복구/정리하고, 재다운로드는 실제 파일 존재와 내용 일치를 확인한다.
기존 import_custom_from_text는 경로만 같으면 다른 폭/재질/아이템도 중복으로 판단한다. 허브 가져오기에서는 이 판정을 그대로 사용하지 않는다. 기존 JSON 가져오기 기본 동작은 보존하면서 정규화·검증 단계를 공유하고, 허브에 한해 전체 플레이 내용 또는 게시물 매핑으로 중복을 판단하는 최소 선택 인자를 추가한다.
로컬 custom_ ID는 항상 새로 안전하게 발급하고 서버 id를 파일명으로 그대로 쓰지 않는다. 같은 경로·다른 폭/아이템의 트랙을 다운로드했을 때 서로 다른 내용과 로컬 기록을 유지해야 한다.
공식 리더보드 제출 제한은 그대로다. 허브 상세/결과에 커뮤니티 트랙은 로컬 기록만 저장됨을 명확히 표시한다. 기존 공식 체크섬과 게임 버전은 변경하지 않는다.

## 6. 구현 파일과 순서

1. TouchControls.gd의 크기 조정과 HUD.gd/TutorialDialog.gd 연동 확인을 독립 변경으로 완료한다.
2. server/app/models.py, schemas.py, main.py/config.py 및 전용 community 라우트/검증 모듈을 최소 추가한다. 기존 세션·설정·CORS·IP 추출을 활용한다.
3. 임시 SQLite DB에서 신규 테이블 생성과 기존 공식 트랙/기록 보존, 서버 API 테스트를 완료한다. 기존 DB에 컬럼 변경이 필요하면 create_all만으로 된다고 가정하지 말고 명시적 마이그레이션을 작성한다.
4. 클라이언트에 작은 CommunityTrackClient와 허브 화면을 추가한다. 기존 LeaderboardClient의 URL/온라인 설정·오류 처리 관례를 확인하되 점수 제출 책임과 섞지 않는다.
5. TrackSelectScreen의 진입·게시와 TrackLoader의 허브 가져오기를 연결한다. 에디터 자체에 별도 게시 기능을 중복 구현하지 않는다.
6. 로컬 API와 실제 클라이언트로 게시→검색→미리보기→다운로드→플레이→삭제를 검증한다.
7. docs/track_editor.md 및 배포 문서에 허브 사용법, 새 제한/설정, DB 백업과 운영자 비공개 처리 절차를 반영한다. 운영 서버에는 배포하지 않는다.

## 7. 완료 조건

- 서버 pytest: 정상 게시·목록·검색·상세·삭제, 잘못된 삭제 토큰, 삭제 후 조회 불가, 413/422/429, 비정상 geometry/NaN/깊은 JSON/과다 점, 개인정보와 토큰 비노출, 기존 리더보드 회귀.
- 목록에서 삭제 데이터 제외, 동률 등록 시 안정 정렬, 제목 특수문자 검색, 빈 결과 처리.
- 클라이언트: 네트워크 오류/타임아웃/취소, 연타, 늦은 응답, 저장 실패, 동일 게시물 재다운로드, 같은 경로·다른 내용, 재시작 후 로컬 목록·매핑, 브라우저 저장 지속성.
- 공식 트랙과 로컬 기존 트랙·기록을 덮어쓰지 않고 커뮤니티 트랙은 공식 기록으로 제출되지 않는다.
- 정상 트랙/하드 오류 트랙 공통 fixture를 서버와 Godot에서 검증하고 판정 차이는 출시 전에 해소한다.
- gdparse/gdlint와 Godot import·부팅 검사, 기존 서버 테스트를 실행한다. 얇은 기능별 회귀 검사를 재사용하며 별도 대형 테스트 프레임워크는 만들지 않는다.
- 1280×720, 844×390, 932×430에서 좌우 조향 버튼 기본/눌림, HUD·효과 카드, 부상/엄마 말풍선, 튜토리얼, 일시정지를 캡처한다. 키보드 모드에는 영향이 없어야 한다.
- 모바일 실제 터치 검증과 데스크톱 --touch-controls 모사는 구분해 보고한다. 실행하지 못한 검증은 완료로 표시하지 않는다.

## 결정한 기본값과 후속 범위

로그인 없는 불변 게시 + 삭제 토큰, 최신순/제목 검색, 로컬 기록 전용을 첫 버전 기본값으로 선택했다. 게시자 계정·수정 이력·랭킹·신고 UI 등은 이 구현에 섞지 않는다. 운영자의 게시물 비공개 수단은 첫 버전에 포함한다.
UI 신규 그림은 필요 없으며 현재 재봉 스킨과 경로 미리보기를 재사용한다. 버전 bump, PR 게시, 실제 DB 변경, 배포는 이 계획의 구현 범위에 포함하지 않는다.
