# 원단별 주행 특성 (FabricProfile)

v2.3.0부터 트랙의 원단(`TrackData.fabric`)은 바닥 렌더뿐 아니라 주행 특성도 바꿉니다. 첫 버전은 트랙 전체에 한 가지 원단 특성을 적용하며, 무작위 미끄러짐이나 무작위 부상은 추가하지 않습니다. 계획과 배경은 `docs/personal-ghost-and-fabric-driving-plan.md` §2에 있습니다.

## 데이터 파일

원단별 배율은 `game/data/fabric_profiles.json` 한 곳에 둡니다. 서버도 이 파일을 복사해 최소 시간 하한을 계산하므로 포맷을 단순하게 유지합니다.

```json
{
  "version": 1,
  "default": "cotton",
  "fields": { "speed": "...", "steer_tau": "...", "risk_gain": "...", "label": "...", "desc": "..." },
  "profiles": {
    "cotton": {"speed": 1.0, "steer_tau": 1.0, "risk_gain": 1.0, "label": "면", "desc": "표준 조작감"},
    "...": {}
  }
}
```

- `speed`는 `speed_table`과 `min_speed`·`max_speed`에 곱하는 배율입니다.
- `steer_tau`는 조향 지연 시간상수 `steer_tau`에 곱하는 배율입니다.
- `risk_gain`은 `risk_gain_rate`에 곱하는 배율입니다.
- `label`은 한국어 원단 이름이고, `desc`는 화면에 보여 주는 한 줄짜리 플레이 차이 문구입니다.
- `fields`는 사람이 읽기 위한 설명이며 게임은 읽지 않습니다.

배율은 0.5 이상 1.5 이하의 숫자여야 합니다. 세 배율 중 하나라도 빠졌거나 범위를 벗어난 원단 행은 무시하고, 그 원단은 아래 fallback 규칙을 따릅니다.

## 현재 계수

계획의 첫 밸런스 표를 그대로 사용합니다. 측정 결과 플레이가 불가능한 조합은 나오지 않았기 때문에 계수를 바꾸지 않았습니다.

| 원단 | 속도 | 조향 지연 | 위험 누적 | 화면 문구 |
|---|---:|---:|---:|---|
| 면 cotton | 1.00 | 1.00 | 1.00 | 표준 조작감 |
| 데님 denim | 0.94 | 0.90 | 0.85 | 조금 느리지만 반응이 빠르고 위험이 덜 쌓임 |
| 실크 silk | 1.04 | 1.15 | 1.10 | 조금 빠르지만 반응이 늦고 위험이 더 쌓임 |
| 니트 knit | 0.98 | 1.08 | 0.95 | 약간 느리고 반응이 조금 늦음 |
| 울 wool | 0.95 | 1.00 | 0.90 | 느리고 위험이 덜 쌓임 |
| 펠트 felt | 0.96 | 0.88 | 0.90 | 느리지만 반응이 빠르고 위험이 덜 쌓임 |
| 새틴 satin | 1.02 | 1.10 | 1.05 | 약간 빠르고 반응이 늦음 |
| 가죽 leather | 0.92 | 0.95 | 0.85 | 가장 느리지만 위험이 덜 쌓임 |

공식 트랙 15개의 원단은 모두 이 8종 안에 있습니다. 길이, 판정 폭, 등급, 패널티 초, 아이템 지속 시간, 부상 사전 연출 시간은 원단과 관계없이 같습니다.

## 적용 공식

런 시작 시 RaceDirector가 `FabricProfile.for_fabric(track.fabric)`의 결과를 `PlayerController.set_fabric_profile`에 한 번 넘깁니다. PlayerController는 배율만 보관하고, 매 틱 전역 `Tuning` 값에 배율을 곱한 effective 값을 씁니다. 전역 `Tuning`은 바꾸지 않으므로 다음 트랙으로 배율이 누적되지 않습니다.

- effective 속도표는 `speed_table[i] × speed`입니다. `reset_state`, 기어 변경, 부상 후 1단 강등, 원단 이탈 복귀가 모두 `effective_speed_for_index` 한 함수를 거칩니다.
- effective 조향 지연은 `steer_tau × steer_tau`입니다.
- effective 위험 누적률은 `risk_gain_rate × risk_gain`입니다. 이 값은 `danger_threshold`를 넘은 틱의 누적에만 쓰이고, 회복률과 골무의 0.95 상한은 그대로입니다.
- 위험 계산의 속도 계수(`inverse_lerp(min, max, speed)`)와 회전력 계산의 `max_speed`도 같은 배율을 곱한 effective 최소·최대 속도를 씁니다. 따라서 같은 기어의 속도 비율은 원단과 관계없이 같고, 회전 각속도도 같습니다. 회전반경만 속도 배율만큼 커지거나 작아집니다.
- 엄마 찬스의 자동 진행 거리는 RaceDirector가 `_player.speed`로 계산하며, 이 값이 이미 effective 속도이므로 따로 바꿀 필요가 없습니다. 같은 값은 `effective_speed()`로도 읽을 수 있습니다.

배율이 모두 1.0인 면은 `x × 1.0 = x`이므로, 원단을 도입하기 전의 물리와 틱마다 비트 단위로 같습니다. 프로필을 넘기지 않은 PlayerController도 면으로 동작합니다.

## fallback

- 표에 없는 원단, 빈 값, `"cotton,silk"` 같은 혼합 문자열은 면 프로필로 달리고 `is_fallback`이 켜집니다. 혼합 문자열을 구간별 원단으로 해석하지 않습니다.
- 대소문자와 앞뒤 공백도 그대로 비교합니다. 바닥 렌더(`FabricSurface`)와 같은 기준을 쓰기 위해서입니다.
- 화면 문구는 "알 수 없는 원단 · 표준(면) 특성으로 주행" 또는 "원단 미지정 · 표준(면) 특성으로 주행"으로 바뀝니다.
- 파일이 없거나 파싱에 실패하면 모든 원단이 배율 1.0으로 달립니다.
- 허브 업로드는 기존 허용 목록 검증을 그대로 유지합니다. 게시자는 원단을 고를 수 있지만 배율을 직접 올릴 수는 없습니다.

## 화면 표시

- 트랙 에디터 속성 줄에서 원단 견본 옆에 "주행: …" 문구를 보여 주고, 툴팁으로 세 배율을 보여 줍니다.
- 공유 허브 상세 화면은 메타 정보 다음 줄에 "원단 주행 특성: …" 문구를 보여 줍니다.
- 트랙 선택 화면 표시는 별도 작업에서 같은 `FabricProfile.describe`를 사용해 추가합니다.

## 측정 결과 요약

`tools/fabric_regression/`이 PlayerController를 스크립트 입력으로 직접 구동해 측정한 값입니다. 시간은 초 단위이고 "-"는 10초 안에 부상이 시작되지 않았다는 뜻입니다. 사람의 실제 플레이 감각을 대신하지는 않습니다.

| 원단 | 5단 풀조향 유지 시 경고 / 부상 | 드리프트 4단 / 5단 부상 | 반전 완료 | 연속 반전 부상까지 3단 / 4단 / 5단 |
|---|---|---|---:|---|
| 면 | 0.63 / 2.08 | 1.87 / 1.05 | 0.73 | 11 / 2 / 1회 |
| 데님 | 0.97 / 2.78 | 2.37 / 1.40 | 0.68 | 18 / 3 / 2회 |
| 실크 | 0.50 / 1.57 | 1.53 / 0.82 | 0.78 | 6 / 2 / 1회 |
| 니트 | 0.63 / 2.12 | 1.93 / 1.07 | 0.77 | 10 / 2 / 1회 |
| 울 | 0.75 / 2.43 | 2.13 / 1.22 | 0.73 | 15 / 2 / 1회 |
| 펠트 | 0.90 / 2.62 | 2.23 / 1.32 | 0.68 | 21 / 3 / 2회 |
| 새틴 | 0.55 / 1.78 | 1.68 / 0.90 | 0.77 | 8 / 2 / 1회 |
| 가죽 | 0.90 / 2.70 | 2.32 / 1.35 | 0.70 | 16 / 3 / 2회 |

- 모든 원단에서 1~2단은 풀조향 유지, 단일 반전, 연속 반전, 드리프트 중 어느 경우에도 부상이 나지 않습니다. 실크의 2단 반전 최대 RISK는 0.05로, 면의 0.03보다 조금 높을 뿐입니다.
- 실크는 0.8초 유지 뒤의 4단 단일 반전에서 부상이 시작됩니다. 면은 같은 입력에서 최대 RISK가 0.97에 그쳐 부상하지 않습니다. 니트와 새틴도 이 경계를 넘습니다.
- 실크의 지연 증가와 위험 배율은 곱셈에 가깝게 겹칩니다. 5단 풀조향 유지의 부상 시간은 면 2.08초, 지연만 실크 1.85초, 위험 배율만 실크 1.80초, 둘 다 실크 1.57초입니다. 두 효과를 따로 곱한 예상값은 1.60초이므로, 이중 적용 때문에 효과가 크게 증폭되지는 않습니다. 속도 배율만 바꾼 경우의 위험 수치는 면과 같습니다.
- 골무 창 안에서는 모든 원단의 RISK가 0.95에서 멈추고 부상이 나지 않습니다.
- 엄마 찬스 2.8초 동안의 5단 자동 진행 거리는 면 840px, 실크 874px, 가죽 773px입니다.
- 스크립트 조향 드라이버로 8개 원단 모두 공식 트랙 15개, 서버 경계 fixture(반경 28.8px U턴, fail 20), 반경 29px 합성 트랙 2개를 원단 이탈 복귀와 부상 없이 완주했습니다. 실크는 회전반경이 4% 커지고 위험이 빨리 쌓여 드라이버가 낮은 기어를 더 오래 쓰므로, 굴곡이 많은 트랙에서는 면보다 완주가 늦었습니다.

## 회귀 검사

`tools/fabric_regression/run.sh`는 game/ 사본에서 다음 항목을 확인합니다.

- 8종 로드, 계획 표와 일치, fallback, 손상된 파일 처리
- v2.2.1 PlayerController 기준본(`baseline/PlayerControllerV221.gd`)과 면 프로필의 틱 단위 비트 동일성
- reset, 기어, 부상, 이탈 복귀, `resolve_cut_pending_now` 경로의 effective 속도
- 위험 배율이 임계 이후 누적에만 적용되는지와 골무 상한
- 여러 원단으로 달린 뒤에도 전역 `Tuning`이 바뀌지 않는지
- RaceDirector 연결(엄마 찬스 진행 거리, 부상·이탈 복귀 속도, 다음 트랙 비누적)
- 최소반경 부근 트랙의 완주와 위 측정 표

사본의 RaceDirector에 원단 적용 호출이 없으면 run.sh가 `_init_player`의 `reset_state` 다음 줄에 한 줄을 임시로 넣고 검사합니다.
