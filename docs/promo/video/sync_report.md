# 홍보 영상 동기·규격 검증 보고서

이 문서는 `overlock_promo_1080p60.mp4` 완성본을 대상으로 수행한 검증 결과를 정리합니다. 모든 수치는 `tools/promo/video/build.sh verify`가 완성본 파일을 다시 디코딩해서 측정한 값입니다. 사람이 음악을 직접 듣고 확인하지는 않았으며, 청취 대신 파형 분석과 디버그 렌더 대조로 동기를 검증했습니다.

## 1. 파일 규격

| 항목 | 값 |
|---|---|
| 컨테이너 | MP4, `moov`가 `mdat`보다 앞에 있습니다(`+faststart`). |
| 영상 | H.264 High, 레벨 4.2, 1920×1080, 60/1fps, 2618프레임, yuv420p, BT.709(primaries, transfer, matrix), 리미티드 레인지 |
| 영상 길이, 비트레이트 | 43.633초, 약 9.56Mbps |
| 오디오 | AAC-LC, 48kHz, 스테레오, 약 256kbps |
| 파일 크기 | 53,590,013바이트(약 51.1MiB) |
| 720p 공유본 | H.264 1280×720, 30fps, 약 2.37Mbps, 오디오는 완성본 스트림을 복사했고, 크기는 14,347,191바이트입니다. |

### 시작 오프셋

- `ffprobe` 기준으로 영상과 오디오 스트림의 `start_time`은 모두 0.000000초입니다.
- 영상 편집 목록(edit list)은 `time=512`(시간 단위 1/15360, B프레임 재정렬 지연 2프레임)를 건너뛰고, 오디오 편집 목록은 `time=2112`(AAC 인코더 프라이밍 샘플)를 건너뜁니다. 따라서 재생기는 영상 프레임 0과 오디오 샘플 0을 같은 시각에 재생합니다.
- 오디오 스트림은 영상보다 15ms 길게 끝납니다(43.648초). AAC가 1024샘플 단위로 인코딩되면서 생긴 끝부분 패딩이고, 이 구간은 페이드 아웃이 끝난 무음입니다.

## 2. 비트 격자

- `music/beatmap.json`의 `beats_sec` 316개에 직선을 맞춰 주기 0.545459초(109.999 BPM)를 얻었습니다. 격자와 원래 비트 목록의 차이는 최대 0.5ms입니다.
- 영상의 0박은 곡의 84번째 비트(45.8555초)이고, 영상은 80박(20마디), 2618프레임입니다. 박 b는 `round(b × 0.545459 × 60)`번 프레임에 놓입니다. 이 반올림 때문에 생기는 오차는 최대 반 프레임(8.3ms)입니다.

## 4. 오디오 정렬

- 완성본의 AAC 오디오를 48kHz로 디코딩해서, 원본 MP3를 같은 방식으로 디코딩한 신호의 45.8555초 지점과 2초부터 40초까지 교차상관을 계산했습니다. 지연은 **0샘플**이고, 정규화 상관계수는 0.9994입니다. 음악을 자르고 리샘플링하고 인코딩하는 과정에서 타이밍이 밀리지 않았습니다.
- 완성본 오디오에서 온셋을 다시 검출했더니 80박 모두 80ms 안에 온셋이 있었습니다. 온셋에서 비트 격자를 뺀 값은 중앙값 -3.0ms, 평균 -3.3ms, 절댓값 90퍼센타일 7.8ms입니다. 가장 큰 차이는 0박의 +22.7ms이며, 0박은 50ms 페이드 인이 걸려 있어서 온셋 검출 위치가 늦게 잡혔습니다.
- 필인의 16분음표 네 개(63, 63.25, 63.5, 63.75박)와 재진입(64박)의 온셋 오차는 각각 -9.2, +1.0, +2.1, +1.7, -0.1ms입니다.

## 5. 디버그 렌더 대조

같은 타임라인을 `--debug-beats`로 한 번 더 렌더하고 같은 음악을 먹싱했습니다. 디버그 렌더에는 박마다 3프레임 동안 우측 상단에 흰 사각형이 켜지고, 강박에는 안쪽에 빨간 사각형이 추가됩니다. 이 표시는 완성본에는 들어가지 않습니다.

- 디버그 파일에서 표시가 켜지는 프레임 80개를 찾았고, 이 목록은 타임라인의 박 프레임 목록과 정확히 같습니다.
- 같은 파일에서 디코딩한 오디오의 온셋과 비교하면 온셋에서 표시 시각을 뺀 값의 중앙값은 -3.0ms입니다. 80박 가운데 79박이 ±1프레임(±16.7ms) 안에 있고, 벗어난 1박은 위에서 설명한 0박(+22.7ms)입니다.
- 샘플 단위 예시로, 드롭(16박)에서 표시는 524번 프레임(오디오 샘플 419,200)에 켜지고 킥 온셋은 샘플 418,944에서 검출되었습니다. 두 값의 차이는 256샘플(5.3ms)이며 1프레임보다 작습니다.

## 6. 라우드니스

| 항목 | 값 |
|---|---|
| 통합 라우드니스(완성본 AAC, EBU R128) | -13.9 LUFS |
| 트루피크(완성본 AAC) | -1.2 dBTP |
| 라우드니스 레인지 | 4.6 LU |
| 샘플 클리핑(±0.999 이상) | 0개 |

- 원곡의 해당 구간은 트루피크가 +0.67 dBTP였습니다. -1.82dB 게인을 적용한 뒤에도 목표보다 높은 피크가 남아서, 샘플 피크 -2.3dBFS에서 동작하는 리미터(ffmpeg `alimiter`, 지연 보상 켬)를 약하게 걸었습니다. 인코딩 전 WAV는 -14.03 LUFS, -1.73 dBTP입니다.
- ffmpeg 내장 AAC 인코더는 이 구간에서 트루피크를 +1.4 dBTP까지 올렸기 때문에 macOS AudioToolbox AAC(`aac_at`)로 바꿨습니다.

## 7. 시각 검수

완성본에서 60프레임(100% 크기 부분 확대 2장 포함)을, 앞선 회차의 렌더에서 100프레임 이상을 직접 열어서 확인했습니다. 여기에는 모든 컷의 직전·직후 프레임, 모든 자막이 등장한 직후와 안착한 뒤의 프레임, 드롭, 필인 스터터 4개, 최종 타이틀, 마지막 프레임이 포함됩니다. 구간별 연속 프레임 시트로 스탬프 등장, 바늘 전환, 줌 펀치, 카운트다운 재매핑의 움직임도 확인했습니다.

- 글자 잘림, 겹침, 한글 두부 글자(tofu)는 없었습니다. 렌더러는 시작할 때 모든 자막 문자열의 글리프가 Pretendard에 있는지, 자막이 화면 가장자리 5% 안쪽에 있는지 검사합니다.
- '오프라인' 표시와 'Press any key to continue' 문구는 어느 프레임에도 보이지 않습니다.
- 계획한 페이드 아웃 전에 평균 밝기가 12/255보다 어두운 프레임은 없었습니다. 마지막 프레임(2617번)만 검은색이며 이것은 의도한 결과입니다.
- 100% 크기로 잘라 본 자막과 출처 표기 글자는 가장자리가 선명했고, 보라색 그라데이션 배경에서 밴딩이나 인코딩 블록은 보이지 않았습니다.
