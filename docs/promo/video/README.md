# Overlock 홍보 영상

이 디렉터리에는 Overlock 홍보 영상 완성본과 편집 자료가 들어 있습니다. 영상은 v2.3.0 빌드를 촬영한 게임 화면에 재봉 모티프 모션 그래픽을 입히고, 모든 컷과 자막을 음악의 박자에 맞춰 배치했습니다. 촬영은 모두 macOS 데스크톱에서 1920×1080 창으로 진행했으며, 모바일 실기기에서 찍은 장면은 없습니다.

## 촬영

촬영 도구는 `tools/promo/capture/`에 있습니다. 저장소의 `game/`은 읽기만 하고, `prepare_copy.sh`가 만든 스크래치 사본에서만 게임을 실행합니다. 사본의 `project.godot`에는 격리 user 디렉터리(`use_custom_user_dir=true`, 이번 촬영에서는 `overlock_promo_capture_v230`)와 촬영 드라이버 autoload만 추가하며, 실행할 때마다 `check_isolation.sh`가 이 설정을 확인합니다. 그래서 실제 사용자 기록(`~/Library/Application Support/Godot/app_userdata/Overlock`)에는 쓰지 않습니다.

촬영 드라이버 `PromoDriver.gd`는 게임 상태를 읽기만 하고, 조작은 모두 키 입력과 마우스 클릭 이벤트를 주입해서 합니다. 시나리오는 다섯 가지입니다.

| 시나리오 | 내용 |
|---|---|
| `heart` | 메인 메뉴 → Start → 트랙 종류 선택(공식 트랙) → 트랙 선택 캐러셀 → 하트 트랙을 두 번 달립니다. 첫 주행에서 기록과 개인 고스트가 격리 user 디렉터리에 저장되고, 결과 화면의 Retry로 시작한 두 번째 주행에서 그 고스트가 앞서 달립니다. 두 번째 주행은 고스트와의 진행도 차이를 70~115px로 유지하도록 기어를 고르고, 두 번째 볼록 구간(s 1370~1780)에서는 Shift를 계속 눌러 긴 드리프트를 만듭니다. |
| `tee` | 긴 직선 가속, 엄마 찬스, 트랙 이탈 꿀밤, 골무, 부상 두 번을 촬영합니다. 아이템은 슬롯에 담긴 뒤 종류별 대기 시간(엄마 찬스 70프레임, 골무 24프레임)이 지나면 Space로 씁니다. |
| `star` | 실크 원단 별 트랙을 자동 드리프트로 달립니다. |
| `cat` | 데님 원단 고양이 트랙을 달립니다. |
| `hub` | 유저 트랙 모드 → 공유 허브 목록 → 게시물 상세 → 다운로드 → 트랙 선택 → 편집 → 에디터 아이템 도구로 엄마 찬스 2개와 골무 3개를 놓습니다. |

`hub` 시나리오는 `hub_server.sh`가 저장소의 `server/`를 임시 SQLite DB로 127.0.0.1에 띄운 로컬 서버를 씁니다. 이 스크립트는 서버 회귀 검사용 트랙 fixture 세 개를 촬영용 데모 게시물로 올리며, 게시물의 제목과 작성자 이름은 촬영을 위해 지어낸 값입니다. `run_capture.sh`는 `BASE_URL`로 127.0.0.1 주소만 받으므로 촬영 중에 운영 서버로 요청하지 않습니다. 나머지 시나리오는 닿지 않는 주소(`127.0.0.1:9`)로 실행해서 메뉴 좌상단에 '오프라인' 표시가 나오며, 메뉴 카드는 이 부분을 잘라 냈습니다.

## 다시 만드는 방법

파이썬 가상 환경을 하나 만들고 아래 명령을 저장소 루트에서 실행합니다.

```bash
python3 -m venv /path/to/venv
/path/to/venv/bin/pip install numpy pillow scipy soundfile librosa skia-python

SCR=/path/to/scratch                     # 저장소 밖의 작업 디렉터리
export PROMO_USER_DIR=overlock_promo_capture_v230

# 1) 촬영용 사본 준비(격리 user 디렉터리, 드라이버 autoload)
tools/promo/capture/prepare_copy.sh "$SCR/copy"

# 2) 촬영(Movie Maker, 1920x1080 60fps). 창이 맨 위에 떠서 화면을 가리므로 촬영 중에는 다른 작업을 하지 않습니다.
for s in heart tee star cat; do
  tools/promo/capture/run_capture.sh "$s" movie "$SCR/runs/m_$s" 1920x1080 "$SCR/copy"
done
tools/promo/capture/hub_server.sh start "$SCR/hub"
BASE_URL="http://127.0.0.1:$(cat "$SCR/hub/hub.port")" \
  tools/promo/capture/run_capture.sh hub movie "$SCR/runs/m_hub" 1920x1080 "$SCR/copy"
tools/promo/capture/hub_server.sh stop "$SCR/hub"

# 3) 편집용 클립(H.264, BT.709 리미티드)과 footage.json
/path/to/venv/bin/python tools/promo/capture/encode_clips.py "$SCR/runs" "$SCR/footage"

# 4) 합성, 인코딩, 검증
PY=/path/to/venv/bin/python WORK="$SCR/work" PROMO_FOOTAGE="$SCR/footage" POSTER_FRAME=1250 \
  tools/promo/video/build.sh all
```

- 같은 입력은 같은 프레임을 만들기 때문에(`--fixed-fps 60`), `encode_clips.py`의 클립 구간은 Movie Maker 프레임 번호로 고정해 두었습니다. 다만 hub 시나리오의 목록이 뜨는 시점은 로컬 서버 응답 시간에 따라 몇 프레임 달라질 수 있으므로, 다시 촬영했다면 `events.jsonl`의 `hub_list`, `hub_detail`, `editor` 프레임을 확인해야 합니다.
- `build.sh video`는 렌더와 인코딩만 수행하고, `build.sh verify`는 검증만 수행합니다.
- 중간 파일(음악 WAV, 영상 단독 트랙, 디버그 렌더, 검증 JSON)은 `WORK`에만 쓰이고 저장소에는 들어가지 않습니다.
- 제작에 사용한 macOS 환경(M1 Pro)에서 heart 촬영은 약 2분 40초, 촬영 다섯 개는 모두 합쳐 10분 안팎, 클립 인코딩은 약 10분, `build.sh all`은 약 6분이 걸렸습니다.
- macOS에서는 AudioToolbox AAC 인코더(`aac_at`)를 사용합니다. 이 인코더가 없는 환경에서는 ffmpeg 내장 `aac`로 바뀌는데, 이 곡에서는 내장 인코더가 트루피크를 약 3dB 올렸으므로 라우드니스 수치를 다시 확인해야 합니다.

## 편집 방식

- 편집 타임라인은 `tools/promo/video/timeline.json`에 비트 번호로만 적혀 있습니다. 초와 프레임은 `music/beatmap.json`의 비트 목록에 직선을 맞춘 격자(주기 0.545459초, 잔차 최대 0.5ms)에서 계산합니다. 따라서 타임라인에 초 단위 값을 직접 적지 않습니다.
- `render.py`는 촬영본을 BT.709 리미티드 레인지로 정확히 디코딩한 다음 skia로 모션 그래픽을 합성하고, 결과 프레임을 곧바로 x264에 넘깁니다. 중간 인코딩을 거치지 않으므로 화질 손실은 최종 인코딩 한 번뿐입니다.
- 촬영본의 속도를 바꿀 때는 프레임을 섞지 않고 원본 60fps 프레임 가운데 하나를 골라 씁니다. 그래서 잔상이 생기지 않습니다. 카운트다운(약 1.8배), 가속 구간(약 1.19배), 엄마 찬스(약 1.07배), 완주 줌아웃(약 1.15배)은 빠르게, 골무 장면의 담기에서 사용까지(0.4초를 1박으로, 약 0.73배)는 느리게 재매핑해서 숫자 전환, 기어 변경, Space 사용, 등급 표시가 박자 프레임에 정확히 떨어지도록 했습니다.
- 긴 원단 주름 장면은 재매핑하지 않고 1배속 그대로 씁니다. Shift를 누르는 순간이 36박에 오도록 맞췄고, 주름이 솟아 있는 1.5초와 가라앉는 구간이 모두 이 샷 안에 들어갑니다.
- 부상 장면에서는 게임이 직접 띄우는 대사 말풍선을 주인공으로 두었습니다. 부상 클립은 사전 연출(0.20초)이 강박 직전에 시작하고 부상 프레임이 50박 강박에 떨어지도록 시작점을 역산했습니다.
- 촬영본 확대는 최대 1.22배입니다. 박자마다 들어가는 줌 펀치는 강박에서 4.5%, 약박에서 1.4%이고 드롭(16박)에서만 10%입니다.
- 전체 화면 섬광은 드롭(16박)과 재진입(64박) 두 번뿐입니다.
- 촬영 환경에서 생긴 '오프라인' 표시는 메뉴 카드를 자를 때 잘라 냈고, 완주 화면 하단의 'Press any key to continue' 문구는 화면 하단을 배경색 그라데이션으로 덮어 가렸습니다.
- 골무 장면(44~48박)은 꿀밤 장면 바로 뒤의 촬영본이라 엄마 꾸중 말풍선이 함께 보입니다. 영상에서는 꿀밤 장면(52박)보다 앞에 놓이므로 순서가 실제 플레이와 다릅니다.
