Overlock의 finger cut 발생 시 기본 캐릭터의 아픈 표정 초상화와 랜덤 대사가 있는 하단 말풍선을 추가해줘. 계획만 작성하지 말고 구현·검증해줘.
현재 Claude/Fable 오케스트레이션 지침을 읽고 해당 흐름을 사용하되, 현재 브랜치와 git status를 먼저 확인하고 사용자 작업을 보존해줘. 다른 worktree에서 작업한다면 아래 새 자료만 가져오고 소스 전체를 덮어쓰지 마.

자료
- 컨셉: docs/concepts/finger-cut-dialogue-v1.png
- 적용할 초상화: game/assets/gfx/ui/player_hurt_teary.png
- 생성 프롬프트: docs/concepts/finger-cut-dialogue-prompts.json
- 선행 손 미끄러짐 기믹: docs/concepts/claude-finger-slip-cut-implementation.txt
이 요청은 선행 기믹에 추가되는 대사 연출이다. 선행 작업이 진행 중이면 통합하고, 이미 구현됐다면 중복 구현하지 마.

요구사항
1. 실제 finger cut 한 번마다 아래 세 문구 중 하나를 같은 확률로 한 번 선택해 표시한다.
   아얏!
   아파!
   아이고!
   느낌표 포함 정확한 문자열. 한 말풍선에 하나만 표시하고 프레임마다 바꾸지 않는다. 연속 같은 문구도 허용한다.
2. 말풍선 자체의 왼쪽 상단에 눈물이 맺힌 기본 캐릭터 초상화를 걸친다. 화면 왼쪽 상단이 아니다. 초상화 머리는 패널 위, 어깨는 패널 왼쪽 아래에 붙고 대사는 오른쪽에 놓인다.
3. off-fabric 엄마 말풍선과 같은 베이지 원단·보라 박음질·갈색 글자 스타일을 재사용한다.
4. 손 미끄러짐/놀람 사전 연출이 아니라 실제 cut의 부상 SFX·밴드·스턴이 발생하는 시점에 표시한다. pending이 보호 효과나 리셋으로 취소되면 말풍선도 발생하지 않는다.
5. off-seam/원단 이탈 강제 복귀에는 기존 엄마 초상화와 “이녀석, 제대로 해야지!”를 유지한다. 그때 이 대사를 추가하지 않는다.
6. 밴드 최대 단계 이후 발생한 실제 cut에도 표시한다. 밴드 단계 증가 성공 여부에 대사 발동을 묶지 않는다.
7. 화면 뒤의 큰 캐릭터 얼굴은 기존 injured 연출을 유지한다. 새 PNG는 말풍선 초상화 전용이며 eyes_surprised나 배경 얼굴을 대체하지 않는다.

확인된 기존 코드 (구현 시 최신 상태 재확인)
- game/scripts/ui/Toast.gd에는 이미 push(message: String, portrait: Texture2D = null)가 있다.
  큐 항목은 text와 portrait를 함께 저장하며 기존 초상화 말풍선 스타일, 종횡비 유지, 그룹 페이드, 일반 스타일 복원을 지원한다.
  새 대화 시스템·새 씬·새 패널 에셋을 만들 필요 없다.
- game/scripts/presentation/PresentationController.gd는 현재 stun 상승 에지에서 부상 오디오와 _advance_cut_stage()를 호출한다.
  선행 손 미끄러짐 작업이 실제 cut 이벤트를 새로 노출했다면 그 공통 이벤트 경로를 사용한다.
  대사 표시 때문에 consume_just_cut()을 별도로 소비해 RaceDirector의 cuts 집계를 빼앗지 마.
- off-fabric 분기는 이미 _toast.push("이녀석, 제대로 해야지!", _MOM_SCOLDING_TEX)를 호출한다.

최소 구현 방향
- PresentationController에서 새 초상화를 preload하고 세 문구 배열을 둔다.
- 표현 전용 RandomNumberGenerator 인스턴스를 한 번 초기화해 randi_range(0, 2)로 선택한다. 기존 표현 전용 RNG가 있으면 재사용한다.
- 전역 randi()/Array.pick_random()으로 게임 아이템·트랙 등 시뮬레이션 난수열을 바꾸지 않는다. 이 UI 대사 때문에 시뮬레이션 저장 형식이나 리플레이 포맷을 바꾸지 않는다.
- 선택된 문구와 초상화를 기존 Toast에 함께 전달한다. 발생당 1회, 실제 표시 중에는 문구 고정.
- 기존 Toast는 약 4초 동안 FIFO를 점유한다. 따라서 이전 아이템 알림/엄마 대사가 떠 있으면 단순 push는 아픈 순간과 어긋날 수 있다.
  일반 push의 동작을 유지하면서 cut만 현재 알림에 우선해 즉시 표시하는 최소 경로를 검토·구현해라. 일반 대기 큐는 유지하고 중단한 현재 알림은 종료한다. 연속 cut은 현재 cut을 새 대사로 갱신해 지난 부상 대사가 뒤늦게 쌓이지 않게 한다.
  이 경로가 필요하면 기존 Tween을 중단하고 대기 중인 process_frame 이후 오래된 표시 작업이 다시 배치/페이드하지 않도록 수명 처리를 확인한다. 범용 우선순위 시스템은 만들지 않는다.
  같은 틱에 cut과 off-fabric이 겹칠 경우 실제 판정 이벤트 순서를 확인하고 패널이 겹치거나 초상화가 섞이지 않도록 한 말풍선씩 표시한다.

에셋·배치
- player_hurt_teary.png: 1254×1254 RGBA PNG, 보라 머리띠·보라 눈·갈색 머리의 기본 캐릭터, 눈물 맺힌 표정, 크림 바느질 스티커 외곽. 글자와 말풍선은 포함하지 않는다.
- 기존 _PORTRAIT_SIDE=212, 본체 680×82, 글자 40, 하단 여백 38 (1280×720 논리 캔버스)를 시작점으로 그대로 재사용한다.
- TextureRect.STRETCH_KEEP_ASPECT_CENTERED를 유지한다. PNG를 늘이거나 눌러 맞추지 않는다.
- 컨셉의 하단 “랜덤 대사: ...” 띠는 설명용이며 인게임에 넣지 않는다. 컨셉이 기존 손/얼굴/노루발 비율을 다르게 그렸더라도 그 부분을 따라 바꾸지 않는다.
- 컨셉의 밴드 손가락 위치는 생성 이미지의 오차다. 기존 cut 단계별 실제 밴드 에셋을 유지하고 컨셉을 따라 엄지로 옮기지 않는다.
- 대사는 Label로 렌더링한다. 그림과 패널·글자는 같이 나타나고 같이 사라져야 한다.
- 노루발, RISK, 속도계, 조작 안내·터치 버튼을 가리지 않게 하고 모든 새 Control은 입력을 통과시킨다.

검증
- 기존 검사와 Godot import/파싱 검사를 실행한다.
- 최소 회귀 검사 하나에서 실제 cut마다 호출 1회, pending/취소/off-fabric만으로는 호출 없음, 문구가 정확한 세 문자열 중 하나, portrait가 올바른지 확인한다.
- 난수 결과가 세 문구를 모두 포함하는지 확률에 기대어 검사하지 말고 고정 시드나 테스트 전용 문구 지정으로 세 표시를 각각 확인한다.
- 실제 RISK 상승으로 cut을 재현해 미끄러짐 → 부상+말풍선 순서를 캡처한다. 상태 직접 주입 검사는 실제 입력 플레이와 구분한다.
- 일반 토스트 표시 중 cut, 엄마 말풍선 후 cut, 연속 cut, 마지막 밴드 단계 이후 cut, 골무/엄마 보호, 재시작·일시정지 및 종료를 확인한다. 오래된 Tween·큐 항목·초상화가 남지 않아야 한다.
- 1280×720 및 가로 모바일 비율에서 세 문구와 페이드 종료를 캡처한다. 실기기 검사가 아니면 데스크톱 모사라고 명시한다.
- 완료 보고에 변경 파일, 선택/표시 타이밍, 큐 충돌 처리, 캡처 경로, 검사 결과와 미검증 항목, 오케스트레이션 실행 여부를 적어줘. 커밋·push·배포는 요청하지 않았다.
