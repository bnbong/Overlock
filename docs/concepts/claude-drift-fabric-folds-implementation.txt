Overlock의 평면 드리프트 스키드를 원단이 옆으로 밀리며 입체적으로 주름지는 연출로 개선해줘. 다음 자료를 읽고 구현·실제 화면 검증까지 진행해줘.

자료
- 컨셉: docs/concepts/drift-fabric-folds-v1.png
- 높이맵: game/assets/gfx/drift_folds/fold_height.png
- 에셋 사용법: game/assets/gfx/drift_folds/README.md
- 생성 기록: docs/concepts/drift-fabric-folds-prompts.json

사용자 의도
드리프트할 때 바닥에 선을 그리는 대신, 손바닥에 밀린 바닥 원단이 낮고 둥근 주름으로 위로 솟아야 한다. 능선의 높이·골짜기·접촉 그림자와 시간에 따른 부풀기/완화가 읽혀야 한다.
원단 위에 별도 조각이 얹힌 느낌, 타이어 자국, 연기·물결·돌·찢어진 천으로 보이지 않게 한다.
컨셉은 형태 설명이다. 컨셉에 생성 과정에서 남은 “원단 이탈…” 토스트는 이 기능과 무관하므로 추가하지 마. 중앙 재봉선, HUD, 캐릭터/손/노루발 크기와 기존 원단/트랙 배색을 컨셉 때문에 바꾸지 마. 큰 주름 높이도 설명용 강조이므로 실제 게임에서는 더 낮게 튜닝한다.

작업 전
현재 git status, 프로젝트 Claude/Fable 지침과 작업 브랜치를 확인한다. 다른 작업자가 고스트·원단 물리·에디터를 수정 중일 수 있으므로 최신 호출부를 읽고 사용자 변경을 보존한다. 이 작업은 표현 개선이며 물리·RISK·판정·아이템·고스트 기록 결과를 변경하지 않는다.

현재 구조
- DriftSkid.gd는 SubViewport 월드에서 그림자/하이라이트 draw_line 두 개를 그린다. fabric_mode7.gdshader가 이를 평평한 바닥 텍스처로 원근 변환하므로 실제 높이 성분이 없다.
- PresentationController는 드리프트 중 push(pos, dir, intensity)를 호출한다.
- 근경 버퍼 120, 완주용 버퍼 400 상한과 공간 샘플링이 있다. 기존 나이 alpha는 실제 시간이 아니라 배열 순서 기반이다.
- FinishView는 get_full_marks를 받아 별도의 선 표현으로 그린다. 주행 화면만 바꾸면 완주 줌아웃에서 다시 평면 줄무늬가 되므로 같이 확인한다.
- ItemBillboardLayer와 기존 투영 계산을 확인하고 좌표계를 재사용한다.

권장 구현
1. 기존 DriftSkid를 주름 발생 위치·진행 방향·강도·생성 시각을 보관하는 표현 데이터 소스로 활용한다. 무조건 새 파티클/물리 시스템을 만들지 않는다.
2. 높이를 가진 작은 격자 패치를 Mode 7과 같은 카메라 좌표로 화면에 투영하는 2.5D 메시 방식을 우선 검토한다. 전체 게임을 3D로 전환하지 않는다.
   각 패치의 바닥 world 좌표와 fold_height의 높이를 사용한다. h=0이면 기존 바닥 투영과 정확히 같은 위치가 되어야 한다. 멀수록 화면 높이가 줄고 가까울수록 높아지는 원근을 적용한다. 평면에 PNG를 붙이고 밝기만 바꾸는 것으로 완료하지 마.
   공유 격자 약 16×16 셀에서 시작하고 결과에 따라 조정한다. 같은 패치마다 독립 노드 수백 개를 만드는 대신 제한된 메시/버퍼를 사용한다.
3. 원단 컬러는 기존 바닥 source_tex의 원래 world UV 또는 동등한 월드 정렬 원단/재봉선 샘플에서 가져온다. 화면 색을 잡아 늘이거나 보라색 PNG를 모든 원단에 붙이지 않는다.
   피드백 샘플링을 피하려면 솟은 주름 레이어를 원본 바닥 SubViewport에 다시 합성하지 않는다. 패치 위치와 텍스처 UV가 같은 월드 좌표를 가리켜야 천 무늬가 미끄러지지 않는다.
4. 높이 gradient로 완만한 명암을 만들고 접지 그림자를 밑면에 남긴다. 높이와 패치 가장자리는 0으로 감쇠해 사각 경계·떨어진 조각처럼 보이는 현상을 막는다. 셰이더 UV 왜곡만을 대안으로 택한다면 실제 영상에서 능선 높이와 국소 가림이 충분히 읽히는지 입증한다.
5. 레이어는 바닥 위, 손·노루발·HUD 아래. 멀리 있는 패치부터 그려 겹침 순서를 맞추고, 카메라 뒤/수평선 인근의 투영 폭주를 클리핑한다.
   중심 재봉선과 바늘 접촉점은 가급적 평평한 좁은 구간으로 남긴다. 노루발을 가리지 않고, 아이템이 주름 속으로 완전히 사라지지 않게 확인한다.

움직임
- 실제 드리프트 방향과 손 누름 방향으로 원단이 모이게 한다. 기존 부호를 추정으로 뒤집지 말고 좌/우 각각 캡처해서 확인한다.
- 높이: 기본 world 0→최대 약 4~10 단위를 튜닝 시작값으로 사용한다. 이 숫자는 확정 스펙이 아니며 1280×720 근경에서 몇 px 솟는지 보고 조정한다.
- 생성 후 약 0.08~0.15초에 솟고, 드리프트 종료 후 약 0.35~0.65초 동안 낮아지는 값을 시작점으로 삼는다. 갑자기 나타나거나 슬로모션 젤리처럼 흔들리지 않게 한다.
- 완전히 사라지기보다는 낮은 주름 흔적을 남겨 완주 시 재봉 결과와 함께 보이게 한다. 잔여 흔적은 단순 음영으로 낮은 비용에 표시해도 된다.
- 드리프트 종료와 재시작, 원단 이탈 강제 복귀, 순간이동에서 스트로크를 끊는다. 멀리 떨어진 두 드리프트 구간 사이에 능선을 이어 그리지 않는다.
- 선회 반전 시 기존 패치의 방향을 통째로 뒤집지 않고 새 구간을 만든다.
- 높이 진행 시간은 주행 표현 시간 기준으로 일시정지에서 멈춘다. 카운트다운·결과 전환 시 생성하지 않는다.
- 랜덤 노이즈가 필요하면 표현 전용 RNG로 생성 시 고정한다. 매 프레임 흔들림이나 게임 RNG 변경을 만들지 않는다.

에셋 처리
- fold_height.png 실제 크기는 1254×1254, alpha 없음. R 채널이 높이 데이터다. 검정 배경을 별도 배경 이미지로 그리지 마.
- source_color 없이 데이터로 샘플하고 lossless import를 사용한다. 가장자리 smoothstep 감쇠와 clamp로 값의 안전성을 보장한다.
- 이 이미지의 능선 방향은 세로다. 진행 접선/측방 압력에 맞춰 회전·스케일한다. 좌우 반전과 광원 방향을 구분해 반전 시 그림자가 반대로 비치지 않게 한다.
- 별도 캐릭터·손·원단 컬러 텍스처는 생성할 필요 없다. 현재 원단을 재사용한다.

모바일과 완주
- 근경에서 높이가 실제 보이는 패치만 메시로 렌더링한다. 활성 입체 패치 약 12개, 잔여 흔적은 기존 유계 버퍼를 시작점으로 프로파일링한다.
- 멀리서는 낮은 해상도/음영 표현으로 줄인다. 모든 원경 흔적을 매 프레임 고밀도 메시로 갱신하지 않는다.
- FinishView는 원래 위치와 방향이 같은 낮은 주름 표현을 사용한다. 줌아웃으로 넘어갈 때 흔적이 사라지거나 위치가 튀면 안 된다.
- 기존 get_full_marks 소비자와 리셋 경로를 확인한다. 데이터 형식 변경은 모든 호출자에 함께 반영한다.
- 원단별 물리 기능이 구현돼 있더라도 이 연출이 물리 계수를 다시 바꾸지 않게 한다. 원단별 시각 높이 차이는 기본 구현이 검증된 뒤 최소한으로만 적용한다.

검증 및 완료 보고
- 같은 입력으로 연출 ON/OFF의 주행 위치·시간·RISK·아이템·결과가 같음을 확인한다.
- 좌/우 드리프트, 급반전, 연속 드리프트, 일시정지, 강제 복귀, 재시작, 완주 줌아웃을 캡처한다.
- 면·데님·실크와 폴백 원단, 재봉선 위/밖에서 텍스처·색·마커 가독성을 확인한다.
- 같은 장면의 기존 평면 스키드/새 입체 주름 비교와 “평면→솟음→완화” 짧은 영상을 남긴다. 스크린샷만으로 움직임 검증 완료라고 하지 않는다.
- 1280×720 및 가로 모바일 비율, 가능한 WebGL 환경에서 측정한다. 실기와 데스크톱 모사는 구분한다.
- 패치 개수 상한, draw 비용/프레임 시간, 겹침·수평선 클리핑, 재시작 후 잔여 데이터가 없는지 확인한다.
- 최종 보고에 파일, 사용 에셋, 투영 방식, 높이/시간/패치 상한 값, 검사·캡처 경로, 미검증 항목을 적어줘.
- 버전 변경·커밋·push·배포는 하지 마.

현재 전달 패키지는 컨셉과 높이맵만 준비한 상태다. 엔진 import와 입체 렌더링 적용은 아직 하지 않았다.
