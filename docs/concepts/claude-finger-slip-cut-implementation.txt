현재 저장소에 RISK MAX → 손 미끄러짐·놀람 → 기존 finger cut 순서의 연출을 구현해줘.
프로젝트의 기존 Claude/Fable 오케스트레이션 지침이 있으면 읽고 그 흐름으로 진행해줘.
먼저 현재 브랜치와 작업 중인 변경을 확인하고 보존해줘. palm-contact worktree와 루트 중 실제 최신 구현 위치를 확인하고, 이전 작업을 덮어쓰거나 무단 병합하지 마.

사용자 의도
RISK가 최고가 되면 한쪽 손이 원단에 붙은 상태로 노루발 쪽으로 미끄러지고 캐릭터가 놀란 표정을 지은 다음 기존 finger cut 패널티를 받는다. 기존 부상을 먼저 실행하고 뒤늦게 놀라는 순서가 되어서는 안 된다.
컨셉의 패널 분할과 화살표는 설명용이다. 인게임 카메라·HUD 배치·손 비율·노루발 크기는 현재 구현을 유지한다. 컨셉의 접촉 손가락은 도식적이므로 실제 접촉 앵커는 기존 부상 단계에서 밴드가 붙는 손가락과 맞춰라.

권장 타이밍 (초기값, 실제 플레이로 조정)
1. 위험 최고 도달: 단 한 번 약 0.20초의 사전 연출을 시작한다. RISK는 이 동안 최대값으로 표시한다.
2. 0~0.20초: 대상 손이 점점 빨라지며 안쪽으로 미끄러짐. 즉시 놀란 눈을 보여준다. 반대 손은 기존 동작을 유지한다. 손바닥·손목은 계속 원단에 닿아 있고 그림자도 손과 함께 이동한다.
3. 약 0.20초: 기존 cut 실행. RISK 초기화, 1단 감속, 스턴, cuts 집계, 부상 SFX·셰이크·밴드 단계 증가를 각각 한 번만 실행한다. 눈은 기존 injured로 전환한다.
4. 이후 약 0.12~0.18초: 손을 짧게 바깥으로 움찔했다가 원래 위치로 복귀. 스턴 시간·패널티 수치는 기존 값을 유지한다.
숫자는 튜닝 시작값이다. 새 입력 버튼이나 회피 미니게임은 추가하지 않는다. 피나 상처 이미지는 필요 없다.

수정 지점과 주의점
1) game/scripts/player/PlayerController.gd
현재 _update_risk()에서 risk>=1이면 즉시 _trigger_cut()으로 risk=0, stun_timer 설정, speed_index=1, _just_cut=true가 된다.
따라서 Presentation에서 risk>=1을 감지하거나 밴드만 늦추는 것으로는 올바른 순서가 되지 않는다.
물리 틱에서 진행되는 최소한의 pending/countdown으로 기존 _trigger_cut 호출을 약 0.20초 뒤로 옮겨라. 시작 조건과 중복 방지는 공통 경로에서 처리하고, 실제 cut 패널티는 기존 함수 하나로 유지한다. 렌더 Tween 완료 콜백에서 시뮬레이션 패널티를 발생시키지 마.
pending 동안 risk 회복/재진입으로 연출이 취소·중복되지 않게 한다. 일반 조작은 기존 규칙대로 유지하되 추가 조작 잠금이 필요하다면 이유와 영향 범위를 보고한다.
골무 및 엄마 찬스의 기존 부상 방지 규칙을 보존한다. pending 도중 보호 효과가 시작되면 오래된 pending을 해제해서 보호 중이나 보호 종료 직후 예약된 cut이 뒤늦게 터지지 않도록 한다.
reset_state, 재시작, 결과 전환, off-fabric 강제 복귀에서도 pending과 시각 오프셋이 남지 않도록 실제 호출 경로를 확인한다. off-fabric은 별도 기믹이며 새 cut을 발생시키지 않는다.

2) game/scripts/systems/RaceDirector.gd 및 기존 기록/리플레이 경로
현재 simulate 후 consume_just_cut()으로 stats를 누적한다. off-fabric 분기에서 조기 return이 있으므로 실제 cut이 발생한 틱의 이벤트가 누락되거나 다음 틱에 중복 집계되지 않는지 확인한다.
새 사전 연출은 물리 delta로 진행하고 기존 입력 재생의 결정성을 유지한다. 관련 직렬화/체크섬이 있다면 필요한 상태만 최소 수정한다.

3) game/scripts/presentation/PresentationController.gd
현재 stun 상승 에지에서 _play_injury_audio(), _advance_cut_stage()가 실행된다. 이 경로를 재사용하고 사전 연출 시작 시에는 실행하지 않는다.
손 선택은 실제 다음 cut 단계와 일치시킨다. 현재 1/3단계는 화면 오른손, 2단계는 화면 왼손이다. 마지막 밴드 단계 이후에도 발생하는 cut의 손 선택을 명시적으로 유지하며 배열 범위를 넘지 않는다.
사전 연출 진행률을 HandView와 BackgroundFace에 전달하는 최소 연결만 추가한다. 별도 범용 연출 관리자나 새로운 의존성은 필요 없다.

4) game/scripts/presentation/HandView.gd
기존 palm_contact 이미지를 그대로 움직인다. 새 손 이미지나 변형 셰이더는 필요 없다.
_draw()의 기존 조향·진동·엄마 교대 오프셋과 충돌하지 않는 추가 slip/recoil 오프셋을 적용한다. _draw_hand_tex()의 손과 접촉 그림자는 같은 변환을 공유해야 한다.
DISPLAY_SIZE=630x472.5의 4:3 비율을 유지하고 x/y 비율을 따로 눌러 팔이 납작해지는 회귀를 막는다.
노루발 위치까지 손 노드 중심을 보내지 말고 실제 대상 손가락 끝 앵커를 맞춘다. 현재 크기에서 이동 거리·살짝 위로 가는 양을 플레이로 보정한다. 손 전체가 중앙 트랙을 덮거나 바늘을 통과하지 않게 한다.
엄마 교대 중에는 아이 손 미끄러짐이 엄마 손에 전이되지 않게 한다. 골무·밴드 텍스처 상태와 양손 미러링도 보존한다.
속도선이나 작은 접촉 섬광이 필요하면 Godot 기본 draw로 짧게 표현한다. 전체 화면 섬광은 추가하지 않는다.

5) game/scripts/presentation/BackgroundFace.gd
base_clean + 눈 오버레이 구조에 surprised 상태를 추가한다. pending일 때만 놀란 눈, 실제 cut 이후에는 기존 injured. bonk·엄마 전환의 우선순위와 타이머 종료 시 refresh를 확인한다.
새 에셋은 실제 RGBA PNG 1672x941이다. 기존 눈은 1280x720. 새 이미지의 검정처럼 보이는 빈 영역은 실제 투명 alpha이며 배경을 제거할 필요 없다.
생성기가 원본과 정확히 같은 픽셀 위치를 보장하지 않았으므로 단순 교체만으로 정렬 완료라고 가정하지 마라.
새 눈을 기존 eye_rect에 정규화해 그린 뒤 surprised 전용 위치 보정을 사용한다. 시작 추정값: eye_rect.size * Vector2(-0.017, -0.04)만큼 위치 이동. 이 값은 실측 확정값이 아니므로 화면에서 눈 중심·눈썹·앞머리 겹침을 확인하고 조정해라.
기존 eyes_offset_y=50, eyes_scale=0.9와 얼굴 크기/위치를 전체적으로 바꾸지 않는다. 새 표정의 정렬 보정만 분리하고 크로스페이드 양쪽 표정에 맞는 rect를 사용한다.
놀람이 충분히 빨리 읽히도록 긴 기존 fade에 묻히지 않게 한다. 엄마 얼굴에 아이의 보라색 눈을 합성하지 않는다. 엄마 찬스는 원래 부상 방지이므로 새 엄마 놀람 에셋은 불필요하다.

검증 및 완료 조건
- 프로젝트 기존 검사부터 실행하고, 새 순서를 검증하는 최소 회귀 검사 하나를 추가한다: MAX 직후에는 cut 집계·스턴·밴드 변화 없음 → 사전 연출 종료에서 정확히 1회 cut → 이후 틱에 중복 없음.
- 정상 플레이에서 RISK를 올려 발동시키고, 검사 전용 강제 발동은 별도라고 보고한다.
- 실제 화면을 연속 캡처/짧은 영상으로 남겨 MAX / 미끄러짐 중간 / 접촉·injured / 복귀를 확인한다. 코드 검사만으로 시각 검증 완료라고 하지 않는다.
- 좌·우 손 부상 단계, 최대 단계 이후 재부상, 골무 활성/만료, 엄마 진입/복귀, pending 중 off-fabric, 재시작, 일시정지/복귀를 확인한다.
- 손 비율, 그림자 접촉, 중앙 트랙 가시성, 최대 좌우 머리 기울기에서 얼굴 절단면, surprised 정렬을 확인한다. 낮은 렌더 FPS에서도 cut 순서·집계가 유지되는지 검사한다.
- 에셋 Godot import 및 프로젝트 파싱/기존 테스트를 확인하고, 실제 수행한 검사와 미수행 항목을 구분한다.
- 완료 보고에 변경 파일, 실제 타이밍, 손 이동량, 표정 정렬값, 캡처 경로, 오케스트레이션 실행 여부를 적어줘.

현재 이 전달 패키지는 컨셉아트와 눈 PNG만 준비한 상태다. 게임 로직은 아직 변경하지 않았으며, 위 튜닝값도 실제 인게임 적용 후 검증해야 한다.
