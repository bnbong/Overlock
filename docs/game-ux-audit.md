# 게임 전체 UX 점검

2026-09-30. 트랙 에디터는 별도 계획에서 다루므로 이번 점검은 메인·트랙 선택·설정·리더보드·공유 허브·주행·결과 흐름에 집중했다. 가장 먼저 고칠 부분은 화면을 볼 수 없을 때의 주행 보호, 모바일 메뉴 조작성, 설정 저장의 일관성이다.

## 검증 방식과 한계

- 앞서 만든 격리 game/ 사본에서 Godot 4.6.1 OpenGL로 7개 주요 화면을 실행했다.
- 창 크기 844×390, --touch-controls로 모바일을 모사했다. 실제 16:9 게임 렌더 영역은 약 693×390이며 나머지는 레터박스다.
- 온라인 URL을 비활성화하고 결과 데이터는 주입했다. 운영 서버에 기록·게시물을 보내지 않았다.
- 메뉴/버튼 크기 및 설정 value_changed를 실행했고, 입력·비동기 요청·종료 흐름은 소스를 추적했다.
- 네트워크 지연 순서 역전, 브라우저 백그라운드/화면 회전, 모바일 실기 터치, 온라인 허브 게시·삭제, 수동 전체 레이스는 이번에 재현하지 않았다.
- 아래 “코드 확인”은 해당 경로의 구현을 확인했다는 뜻이며 모든 기기에서 재현했다는 뜻은 아니다. “제안”은 결함 확정이 아닌 사용성 개선이다.
- 제품 소스는 변경하지 않았다. [실행 로그](game-ux-audit/survey.log)에 버튼의 논리 크기가 있다. 설정 저장 파일은 초기화하지 않은 격리 상태라 비어 있었으며, 이 값만으로 디스크 저장 실패를 판정하지 않았다.

## 우선순위

### P1 화면 회전과 포커스 상실 때 주행 보호

**코드 확인.** OrientationGuard._refresh는 안내 표시만 전환하고, 코드상 시뮬레이션·입력 차단에 관여하지 않는다. TouchControls는 포커스를 잃으면 입력을 해제하지만 RaceDirector에는 동일 사건으로 일시정지하는 경로가 없다.

세로 안내가 화면을 덮는 동안 주행이 계속될 수 있다. 브라우저 백그라운드에서는 브라우저 자체 throttling 여부도 영향을 주므로 실기 검증이 필요하다.

개선: 주행/카운트다운 중 세로 전환 또는 포커스 상실 시 자동 일시정지하고 입력을 해제한다. 복귀 시 “계속”을 눌러 재개하게 한다. 수동 일시정지와 자동 정지를 구분해 회전 복구가 수동 정지를 풀지 않게 한다. 메뉴·결과에서는 주행 정지를 새로 걸지 않는다.

검증: 가로→세로→가로, 탭 전환, 화면 잠금, 포커스 복귀에서 시간·이동·RISK가 정지하고 눌림 상태가 남지 않는지 확인.

### P1 모바일 메뉴와 결과 화면의 작은 조작 영역

**실행·캡처 확인.** 720 논리 높이를 390으로 축소하므로 높이 48 버튼은 약 26, 56 버튼은 약 30 화면 px다. 트랙 전환 화살표, 설정 저장/뒤로, 허브 검색/뒤로, 결과 재도전/메뉴가 해당한다. 메인 닉네임 버튼은 논리 높이 32로 더 작다.

[트랙 선택](game-ux-audit/ux-TrackSelect.png), [설정](game-ux-audit/ux-Settings.png), [결과](game-ux-audit/ux-Result.png), [허브](game-ux-audit/ux-CommunityHub.png).

개선: 인게임 좌우 버튼을 추가 확대하는 것이 아니라 메뉴 화면에 터치 전용 배치를 적용한다. 디자인 목표는 실제 화면 기준 약 44~48px 높이이며, 고정 논리 크기만 키워 넘치게 하지 말고 여백 축소·세로 스크롤·행 재배치를 함께 사용한다. 긴 닉네임·트랙 이름·한국어 문자열도 확인한다.
사용자가 이전에 요청한 좌우 조향 버튼 한정 변경과는 별도 후속 작업으로 제안한다.

### P1 설정의 저장과 취소 의미 통일

**실행 및 코드 확인.** SettingsScreen에서 슬라이더 value_changed는 음량/조향을 즉시 반영하지만 저장은 drag_ended 또는 저장 버튼에서 한다. 뒤로 가기는 저장하지 않는다. 키보드로 변경 후 뒤로 가면 현재 세션만 달라지고 다음 실행에서는 이전 값으로 돌아갈 수 있다. 마우스 드래그는 저장을 누르지 않아도 이미 영속돼 있어 사용자가 같은 규칙으로 예상하기 어렵다.

NicknameDialog는 기존 닉네임을 수정한 후 Esc를 눌러도 _do_confirm으로 변경을 저장한다. save_nickname 실패 반환값도 확인하지 않고 닫는다.

개선: 소리·조향은 모든 입력 방식에서 자동 저장하며 실패를 표시하고, 이름은 명시적 저장/취소로 통일한다. 기존 이름 변경에서 Esc는 취소, 최초 방문에서는 기본 닉네임으로 시작을 별도 선택으로 둔다. 설정 화면에 자동 저장 항목임을 표시한다.
자동 저장의 디스크 쓰기는 입력 종료/짧은 지연으로 모으고 프레임마다 파일을 쓰지 않는다.

### P1 빠른 리더보드 전환 시 오래된 응답 혼입

**코드상 경합 위험. 지연 네트워크 재현 미실시.** LeaderboardClient.fetch_leaderboard는 각 비동기 응답을 track_id나 요청 ID 없이 공용 leaderboard_fetched로 전달한다. LeaderboardScreen._on_fetched는 현재 선택과 대조하지 않고 그린다.

A 조회 직후 B로 바꿨는데 A 응답이 늦게 오면 B 제목 아래 A 기록이 표시될 수 있다. 씬을 나갔다가 재진입했을 때도 진행 중인 이전 요청을 고려해야 한다.

개선: 조회별 세대 번호와 트랙/난이도를 전달해 현재 요청만 반영한다. 기존 허브의 취소/응답 관리 관례를 참고하되 큰 통신 계층 재작성은 필요 없다. 같은 화면에 다시 시도 버튼도 추가한다.
검증: 지연 서버로 A→B→C 응답을 역순 반환하고 C만 표시되는지, 화면 재진입 후 이전 응답이 섞이지 않는지 확인.

### P2 오프라인 결과 화면에서 제출 불가 이유 안내

**실행·코드 확인.** ResultScreen._setup_submit은 공식 트랙도 오프라인이면 제출 버튼을 숨긴다. 커뮤니티 트랙에는 로컬 기록 안내가 있지만 일반 공식 트랙 오프라인에는 같은 수준의 이유 안내가 없다.

개선: “기록은 이 기기에 저장됨 · 서버 연결 후 제출 가능” 등 실제 상태를 표시하고 연결 재시도/수동 제출 경로를 제공한다. 저장되지 않은 기록을 저장됐다고 표시하지 않는다. 재시도 시 health 상태도 새로 확인한다.
첫 개선은 현재 결과 화면에서 재시도로 제한한다. 영구 오프라인 제출 큐는 중복 제출/버전/보관 정책이 필요하므로 별도 기능으로 둔다.

### P2 공유 허브에서 시작한 플레이의 복귀 위치

**코드 확인.** CommunityHubScreen._download(true)는 일반 GameState.start_run을 사용한다. 결과 메뉴는 TrackSelect, 일시정지 메뉴는 Main으로 가므로 출발한 허브 상세로 돌아오지 않는다.

개선: 허브에서 출발했을 때 “허브로 돌아가기”를 제공하고 선택 게시물·검색어·목록 위치를 복원한다. 상세 게시물이 삭제된 경우 목록으로 복귀하며 사유를 표시한다.
에디터 테스트 복귀 계획의 작은 실행 출처 구조와 함께 설계하되 허브 일반 플레이를 editor_test로 취급해 로컬 기록을 막지 않는다.

### P2 트랙이 많아질수록 비효율적인 선택 화면

**코드 확인 및 제안.** 공식 목록 뒤에 모든 로컬 트랙을 합쳐 좌우 캐러셀로 순환한다. 커뮤니티 다운로드가 늘면 공식/내 트랙/다운로드 트랙을 찾기 위해 여러 번 눌러야 한다.

개선: 공식 / 내 트랙 / 다운로드 구분과 제목 검색 또는 간단한 목록 선택을 추가한다. 첫 단계는 탭+목록이면 충분하다. 선택 시 출처·제작자 표시명·로컬 기록 여부를 구분하고 마지막 선택을 복원한다. 제작자 표시명을 인증된 신원처럼 표시하지 않는다.

### P2 튜토리얼을 다시 볼 수 없음

**코드 확인.** tutorial_seen은 전역 한 번 설정되고 Settings/Main에는 다시 보기 진입점이 없다. 키보드로 처음 본 뒤 터치 모드로 바뀐 사용자도 안내를 다시 열기 어렵다.

개선: 설정 또는 일시정지에 “조작 안내”를 추가한다. 현재 입력 방식에 맞는 안내를 보여주고 닫은 뒤 기존 일시정지를 유지한다. 첫 실행 플래그를 지우거나 매번 강제 안내하는 방식은 피한다.
RISK·드리프트·부상 및 “빨라도 재봉 등급이 낮으면 순위가 밀릴 수 있음”을 짧게 설명한다.

### P2 실수로 재시작과 나가기

**코드 확인 및 제안.** RaceDirector._restart와 _to_menu는 확인 없이 실행한다. R 키와 일시정지의 재시작/메뉴에서 진행 중 기록을 잃을 수 있다.

개선: 일시정지에서 진행을 버리는 메뉴 복귀에 확인을 제공한다. 빠른 재도전용 R을 무조건 두 번 누르게 만들지는 말고, 길게 누르기 또는 선택 가능한 확인 여부를 검토한다. 확인창 취소가 플레이를 자동 재개하지 않도록 한다.

### P2 모달과 키보드 내비게이션의 일관성

**코드 확인, 입력 재현 필요.** TrackSelectScreen._input은 모달/텍스트 포커스 가드 없이 A/D·방향키·Esc를 먼저 소비한다. 파일 선택·삭제 확인창과 겹칠 때 배경 트랙 이동이나 화면 이탈이 발생하는지 검증이 필요하다.
MainMenu의 닉네임·개발자 프로필 버튼은 FOCUS_NONE이라 키보드 포커스로 접근하지 못한다. 닉네임은 설정에 대체 경로가 있지만 프로필은 확인이 필요하다.

개선: 모달이 있으면 그 모달이 입력을 소유하고 닫힌 뒤 원래 포커스를 복원한다. 선택 화면 전체의 단축키가 이름 입력/확인창을 가로채지 않게 한다. 키보드로 접근할 필요한 버튼에는 포커스 경로를 제공한다.

### P3 표현과 안내의 일관성

**화면 확인 및 제안.** 한국어 메뉴에 Play/Retry/Menu/Accuracy/Perfect/Cuts가 섞여 있고, 모바일에도 “A/D, Enter, Esc” 힌트가 남는다. 설정의 “조향 감도 / 부드러움”도 값이 커질수록 민감한지 부드러운지 바로 알기 어렵다.

개선: 핵심 행동은 “시작 / 다시 도전 / 트랙 선택”처럼 실제 목적지 기준으로 표기한다. 터치에서는 키보드 힌트를 숨기거나 터치 안내로 바꾼다. 조향 슬라이더에 “즉각적 ↔ 부드러움” 양끝 설명을 넣는다.
결과 화면에는 등급 개선 팁 하나를 표시한다. 전체 번역 시스템이나 새 보상 체계는 이 정리 작업에 넣지 않는다.

## 유지할 좋은 동작

- 웹에서 Quit를 숨기는 분기, 메인에서 온라인 상태 표시와 로컬 저장 안내가 이미 있다.
- 허브는 오프라인/재시도 UI, 삭제 토큰 저장 실패 처리, 다운로드 실패 시 플레이 차단이 있다. 기능 전체가 없는 것으로 보고 재작성하지 않는다.
- 터치 입력은 멀티터치 추적과 포커스 상실·화면 숨김·종료 시 해제가 있다.
- 결과와 허브에서 커뮤니티 기록이 공식 리더보드 대상이 아님을 안내하는 경로가 있다.
- 리더보드에는 내 로컬 기록과 제출 당시 순위를 구분하는 문구가 있다.

## 실행 순서와 완료 기준

1. 주행 중 회전/포커스 상실 보호, 설정 저장/취소, 리더보드 오래된 응답 차단.
2. 모바일 메뉴 터치 배치와 읽기 쉬운 상태 안내.
3. 허브 복귀·트랙 분류/검색·튜토리얼 다시 보기.
4. 문구·키보드 포커스·재시작 보호 정리.

각 변경은 기존 흐름에 작게 적용한다. 실기 iOS/Android 회전·백그라운드, 느린/끊긴 네트워크, 키보드만 사용, 긴 트랙명·닉네임, 최초 실행과 기존 사용자, 정상/커뮤니티 트랙 완주를 인수 시나리오로 삼는다.
스크린샷만으로 입력·네트워크·저장 성공을 판정하지 말고 해당 동작을 재현한다. 이번 진단에서 미재현인 항목은 먼저 실패하는 최소 검사를 만든 뒤 수정한다.
