# 트랙 에디터 UX 검증 및 개선 계획

2026-09-30 현재 루트 체크아웃을 기준으로 기존 에디터를 실행 검증했다. 편집한 내용이 저장·불러오기·테스트 플레이에서 보존되도록 고치는 것을 우선하고, 새 캔버스는 최대 줌아웃으로 시작한다. 그 위에 아이템 배치와 원단 선택의 발견 가능성을 개선한다. 이 문서는 계획이며 제품 소스 수정은 하지 않았다.

## 직접 검증한 결과

Godot 4.6.1 사본을 /tmp/overlock-editor-ux-audit/game에 만들고 별도 user data 이름 overlock_editor_ux_audit_20260930을 사용했다. 원래 게임 기록과 소스는 건드리지 않았다.
헤드리스에서 실제 씬을 생성하고 에디터 콜백·저장·테스트 전환을 실행했다. 별도로 OpenGL 렌더러에서 1280×720 화면을 캡처했다. 손으로 트랙을 그려 완주한 실기 플레이가 아니라 자동 상태 주입·콜백 검증이다.

## 추가로 발견한 코드상 문제

다음은 소스 경로 확인 결과이며 모든 항목을 입력 재현한 것은 아니다.

- _on_stroke_committed는 끝점에서 먼 곳에 그리면 기존 경로를 조용히 교체한다.
- 지우기는 접촉점 이후 경로 전체를 자르는 기능이다. 일반 지우개처럼 일부만 지울 것으로 오해하기 쉽다.
- undo 스냅샷은 경로·닫힘·닫기 전 경로만 포함한다. 이름·난이도·원단·ID는 복원하지 않고 _undo는 dirty를 갱신하지 않는다.
- 난이도 변경은 검증만 무효화하고 dirty를 설정하지 않는다.
- _import_from_text는 closed를 false로 만들고 사용자 지정 width를 난이도 프리셋으로 바꾼다. items/modifiers도 보존하지 않는다.
- 일반 TrackLoader JSON 가져오기에도 items를 보존하지 않는 경로가 있다. 새 허브 전용 가져오기는 items를 검사·보존한다. 에디터만 수정하면 일반 파일 가져오기에서 손실이 남는다.
- Ctrl+Z 처리가 LineEdit 포커스 검사보다 먼저여서 이름 입력 중에도 트랙 실행취소를 가로챈다.
- FIT_TARGET_LENGTH 스케일 후 점 간격을 재샘플하지 않는다. 트림 8개 점의 물리적 길이와 곡률 판정 일관성이 변할 수 있다.
- 기존 완주는 RecordStore.submit을 호출한다. 테스트 플레이 전용 구분이 없으므로 실험용 주행도 일반 로컬 기록 경로를 사용한다.

## 권장 작업 순서

### 1단계 편집 상태와 테스트 복귀

GameState의 기존 씬 전환 구조에 작은 editor_test 실행 출처와 editor_session 스냅샷을 추가한다. 범용 라우터나 새 상태 관리 프레임워크는 만들지 않는다.

스냅샷에는 경로, closed/pre_close, 이름·난이도·원단·폭·아이템, 로컬 ID, 저장 기준 상태, undo/redo, zoom/pan, 선택 도구·선택 아이템을 포함한다. 편집 문서와 화면 상태는 구분한다. 원격 트랙·공식 트랙은 원본을 수정하지 않고 로컬 사본으로 작업한다.

흐름:
1. 유효한 현재 편집본에서 “테스트 플레이”를 누른다.
2. 미저장 변경이 있으면 “저장 후 테스트” 또는 “취소”를 제공한다. 저장 실패 시 출발하지 않는다. 새 트랙은 이름 확인과 저장을 완료한다.
3. 문서와 화면 상태를 스냅샷으로 보관하고 editor_test 출처로 Gameplay에 진입한다.
4. 완주 결과 화면의 주 버튼은 “편집으로 돌아가기”, 보조 버튼은 “다시 테스트”로 표시한다.
5. 일시정지에도 “편집으로 돌아가기”를 제공한다. 재시작은 테스트 출처를 유지한다.
6. 복귀 시 원래 편집 문서·줌·화면 위치·선택·undo를 복원한다. 신규 에디터의 초기화로 덮어쓰지 않는다.
7. 일반 트랙 선택에서 시작한 플레이는 현재 메뉴/결과 흐름을 그대로 사용한다. 정상 종료·에디터 나가기에서 테스트 출처를 정리한다.

테스트 플레이는 결과 통계를 보여주되 공식 서버 제출과 개인 최고 기록 갱신을 하지 않는 방향을 권장한다. RecordStore 호출 지점에서 출처를 구분하고 단순히 결과 화면의 제출 버튼만 숨기지 않는다.
브라우저 새로고침/앱 재실행 복구는 별도 자동 임시저장 단계로 두며, 첫 구현의 메모리 스냅샷을 영속 복구라고 표시하지 않는다.

### 2단계 새 캔버스 최대 줌아웃과 화면 도구

- 새 문서 진입 시 zoom=ZOOM_MIN=0.15. 트랙 복귀 시에는 사용자가 보던 zoom/pan을 복원한다.
- 실제 그리기 영역을 툴바·상태·속성 패널 사이로 제한하고 중앙을 그 영역 기준으로 계산한다.
- “+ / −”, 현재 배율, “전체 보기”를 항상 노출한다. 전체 보기는 경로 bounds와 폭·마커 여백을 포함해 카메라만 조정한다.
- 불러오기·다른 트랙 열기는 전체 보기, 새 문서는 최대 줌아웃, 테스트 복귀는 원래 화면이라는 규칙을 구분한다.
- 길이·현재 배율·시작/끝을 계속 표시한다. 월드 길이를 화면 픽셀과 혼동하지 않도록 “트랙 길이”로 표기한다.
- 최대 줌아웃에서 가는 선과 시작/끝/아이템 마커는 최소 화면 크기를 유지한다. 스냅·선택·지우기 히트 영역도 화면 기준 여유를 적용한다.
- 4 화면 px 샘플 간격은 zoom=0.15에서 약 26.7 월드 단위다. 곡선 처리·재샘플을 검증해 초기 줌만 바꾸고 곡선이 거칠어지는 회귀를 막는다.
- 모바일에서는 그리기/화면 이동 모드를 명시적으로 구분하고 화면 버튼만으로 이동·줌이 가능하게 한다. 휠·중클릭만을 필수 조작으로 남기지 않는다.

### 3단계 길이 조절을 명시적인 편집으로 변경

기존 “길이 맞추기”를 없애고 카메라의 “전체 보기”와 문서 편집인 “트랙 길이 조절…”을 분리한다.
길이 조절 대화상자는 현재 길이, 목표 길이(기본값=현재 길이), 배율, 적용 전후 예상 길이를 표시한다. 3200 자동 강제값은 제거한다.
짧은 트랙에는 권장 범위로 늘리는 선택을 제안할 수 있지만 긴 트랙을 자동 축소하지 않는다. 사용자가 목표 길이를 입력하고 “적용”해야 좌표가 바뀐다. 취소하면 원본 그대로, 적용은 undo 한 단계다.

현재 기준: 권장 2500~4500, 하드 허용 1500~8000. 6000 트랙은 경고가 있어도 유효하며 3200으로 줄일 필요가 없다. 이 개선에서 무조건 검증 상한을 늘리지 않는다.

균일 스케일은 경로 중심 기준으로 수행하고 재샘플·재검증한다. 원단과 판정 폭은 유지한다. 반경과 선 간격이 좁아져 실패할 수 있음을 미리보기 결과에 보여준다. 자동 수정도 원본을 즉시 덮지 말고 적용/취소를 제공한다.

아이템 s는 배율에 따라 같은 진행 비율로 이동시키고 lat는 판정 폭이 그대로이므로 유지한다. 폐곡선 상태도 보존한다. 수치 조정·재샘플 뒤 최종 실제 길이를 사용해 s 범위를 검사한다.

### 4단계 골무와 엄마 찬스 배치

기존 items 스키마를 사용한다: {type: thimble 또는 autopilot, s: 시작부터 호길이, lat: 중심선 옆 거리}. 새 게임 아이템을 추가하지 않는다.

- 도구: 그리기 / 화면 이동 / 끝부분 자르기 / 아이템.
- 아이템 종류를 고른 뒤 경로 클릭으로 배치한다. 초기 lat=0으로 중심선에 스냅한다.
- 아이콘 선택 후 경로를 따라 드래그해 이동하고 삭제할 수 있다. 속성 패널에서 진행 위치와 종류를 확인한다.
- 좌표→최근접 선분 투영→호길이 s 산출을 사용한다. 교차/근접 구간은 선택 마커와 시작부터 거리를 보여 잘못된 구간 배치를 확인할 수 있게 한다.
- 이동·배치·삭제는 각각 undo/redo에 포함한다. 아이템 조작이 새 스트로크를 시작하지 않게 한다.
- 아이템은 최대 128개 및 허브의 타입/s/lat 제약과 맞춘다. 출발/도착과 너무 가까운 배치는 경고하되 임의의 새 하드 규칙을 추가하지 않는다.

경로 편집 후 처리:
- 이어 그리기: 기존 s 유지.
- 길이 스케일: 진행 비율 유지.
- 끝 자르기: 잘린 구간의 아이템을 같은 undo 작업으로 제거하며 제거 개수를 미리 알린다.
- 전체 교체/전체 지우기: 경로와 아이템을 함께 변경하고 undo로 함께 복원한다.
- 곡률 수정·재샘플: 이전 월드 위치를 새 경로에 투영한다. 크게 이동하거나 다의적인 항목은 검토 표시를 하고 해결 전 저장/테스트를 막는다. 조용히 누락하거나 경로 시작으로 몰지 않는다.
- 가져온 lat가 0이 아니면 이를 보존한다. UI가 편집을 지원하지 않는다고 값을 0으로 덮어쓰지 않는다.

### 5단계 원단과 속성 패널

새로운 원단 체계를 만들지 않고 기존 8종 선택을 개선한다. 면·데님·실크·니트·울·펠트·새틴·가죽의 한국어 이름과 기존 원단 견본을 표시한다. 내부 ID는 유지한다.
원단 선택 즉시 견본/선택 상태가 바뀌고 저장 후 실제 게임에 같은 재질이 적용돼야 한다. 재질별 물리 효과를 이번 작업에서 약속하거나 추가하지 않는다.
이름·원단 변경은 dirty를 갱신하지만 기하 검증은 불필요하게 다시 요구하지 않는다. 난이도/폭 변경은 dirty와 기하 검증 상태를 함께 갱신한다.
입력 폭이 프리셋과 다르면 “사용자 지정 폭”을 보여 원본을 보존한다. 프리셋으로 바꿀 때만 명시적으로 폭을 변경한다.
알 수 없는/미지원 필드는 지원 여부를 안내한다. items/width/closed/modifiers를 조용히 버리는 round-trip을 금지한다. modifiers는 실제 소비 코드를 확인한 뒤 허용된 메타데이터만 보존하고 미지원 실행 속성은 거부한다.

### 6단계 편집 안전성과 검증 안내

- 끝점에서 먼 곳에 그릴 때 기존 경로를 자동 교체하지 않는다. “이어 그리기는 끝점에서 시작하세요”를 안내하고 “새로 그리기”는 별도 명시 동작으로 둔다.
- 현재 지우개를 실제 동작에 맞게 “끝부분 자르기”로 명명하고 잘릴 구간을 미리 강조한다. 일반 부분 지우개와 다중 경로는 이번 범위에 넣지 않는다.
- dirty는 현재 저장 가능한 문서와 마지막 저장 문서 비교를 기준으로 일관되게 계산한다. undo/redo·이름·원단·아이템·전체 지우기 모두 반영한다.
- 가져오기 실패는 기존 문서·ID·화면을 바꾸지 않는다. 성공 시 교체 전 미저장 확인을 제공한다. 불러오기의 undo는 메타·아이템까지 복원한다.
- 문서의 전체 상태를 undo 한 단위로 보관하되 제스처 드래그 매 프레임마다 쌓지 않는다. 기존 30단계 상한부터 시작한다.
- 이름 입력의 Ctrl/Cmd+Z는 텍스트 편집에 맡긴다. Delete/Backspace와 확인창에서도 캔버스 단축키를 가로채지 않는다.
- 길이와 저장 상태는 상시 표시한다. 검증 실패는 한 줄 긴 메시지 대신 항목별 사유·해결 힌트와 해당 위치로 이동 기능을 제공한다.
- 검증 기준은 “저장 가능”과 “권장”으로 구분한다. 경고를 없애기 위해 정상 트랙을 강제로 변형하지 않는다.

## 구현 후 인수 검사

1. 새 문서는 zoom 0.15, 불러온 문서는 전체 보기, 테스트 복귀는 기존 zoom/pan. 화면 조작 전후 경로 좌표가 같아야 한다.
2. 실제 포인터 입력으로 짧은 선·긴 곡선·이어 그리기·끝 자르기를 수행한다. 화면 영역 밖 릴리스/취소 후 그리기 상태가 남지 않아야 한다.
3. 1500/2500/4500/6000/8000 경계 주변 길이를 검사한다. 6000 트랙이 자동 축소되지 않고 목표값을 지정한 경우에만 변경돼야 한다.
4. 이름·원단·난이도·폭·아이템 변경, 저장, undo/redo, 가져오기 취소/실패에서 문서와 dirty를 확인한다.
5. 골무·엄마 찬스 여러 개, lat가 있는 아이템, closed 및 사용자 폭이 포함된 JSON을 가져오기→저장→내보내기→재가져오기한다. 필드·아이템 위치·해시 및 허브 재게시 결과를 확인한다.
6. 그리기→검증→저장→테스트→완주→결과→편집 복귀를 실제 주행으로 확인한다. 테스트 중 재시작·일시정지 복귀도 검사하고 문서·undo·배율이 유지돼야 한다.
7. 테스트 기록은 일반 개인 최고와 서버 기록에 섞이지 않고, 일반 플레이의 결과·메뉴 흐름은 유지돼야 한다.
8. 1280×720 및 가로 844×390/932×430에서 툴바·원단 선택·상태·검증·확인창을 캡처한다. 모바일은 줌·화면 이동·아이템 배치까지 키보드 없이 가능해야 한다.
9. gdparse/gdlint, Godot import, 기존 트랙/공유 허브 테스트 및 최소 에디터 상태·전환 회귀 검사를 실행한다. 좌표 변환/길이/아이템 재투영은 허용 오차를 명시한다.

## 검증 범위와 다음 단계

이번 작업에서 확인한 것은 루트 체크아웃의 코드, 자동 씬·콜백 실행, 두 장의 실제 렌더 캡처다. 모바일 실기, 실제 손그리기, 테스트 트랙의 수동 완주, 모든 원단의 인게임 렌더링은 아직 확인하지 않았다.
계획 승인 후 위 단계별로 구현하고, 특히 데이터 보존과 테스트 복귀를 완료한 뒤 아이템 도구를 연결하는 순서를 권장한다. 커밋·배포·실제 사용자 파일 변경은 이 검증에서 수행하지 않았다.
