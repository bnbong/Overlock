# 사실적인 원단 텍스처 후보 v1

2026-10-02. 내장 image_gen으로 생성한 8종 원단의 base-color PNG. 기존 원단 팔레트를 바탕으로 섬유 조직을 표현했다. 생성 프롬프트는 [prompts.json](prompts.json). 이 폴더의 원본은 v2.3.0에서 바닥 원단으로 적용했으며(아래 "적용 상태" 절), 원본 파일 자체는 수정하지 않았다.

8개 모두 실제 출력은 1254×1254, 알파 없는 PNG임을 `sips`로 확인했다(프롬프트의 요청 크기와 다름). 육안으로 재질별 조직과 큰 주름·문자·테두리가 없는 것을 확인했다. 실크와 새틴의 광택은 평면 이미지의 제한적인 표현이며, 동적 반사광까지 포함하지 않는다.

## 적용 상태 (v2.3.0)

- 이 폴더에는 `.gdignore`가 있어 Godot가 원본을 import하거나 내보내지 않는다. 원본은 소스로만 보관한다.
- 런타임 타일은 `make_tileable.py`가 만든 `../fabrics/fabric_<id>.png`(1024², 이음매 처리본)이다. `FabricSurface.FABRIC_DIR`가 이 폴더를 가리키며, felt/satin/wool/leather도 이제 전용 타일을 쓴다. 절차적 바닥은 타일 파일이 없을 때만 그린다.
- import는 무손실 압축, 밉맵 생성, `size_limit=512`이다. 텍스처 해상도와 월드 반복 크기는 분리했으며, 반복 크기는 `FabricSurface.TILE_WORLD`(기본 512, 데님 768, 새틴 640)에 있다. 128 월드 단위로 비교했을 때 조직이 1px 안팎으로 뭉개져 이 값으로 정했다.
- `FabricSurface.FABRIC_BASE`는 가공한 타일의 sRGB 평균색으로 갱신했다. 수평선 위 원경 폴백색과 스와치 배경색이 이 값을 쓴다. 드리프트 주름은 바닥 SubViewport 텍스처를 직접 샘플하므로 `FABRIC_BASE`를 참조하지 않는다.
- 트랙 선택 화면과 트랙 에디터의 견본은 같은 타일에서 바닥 월드 70px에 해당하는 중앙 영역을 잘라 쓴다. 공유 허브는 원단을 글자로만 표시한다.
- 재질별 주행 물리 값은 바꾸지 않았다. 웹 빌드와 실기기 화면은 아직 확인하지 않았다.

## 적용 시 주의할 점

아래는 적용 전에 남긴 점검 목록이다. 위 "적용 상태" 절에 처리 결과를 정리했다.

- `FabricSurface._tile_path()`가 현재 읽는 위치는 상위 `gfx/fabric_<id>.png`이다. 이 폴더의 파일은 아직 런타임에 연결되지 않았다. felt/satin/wool/leather는 현재 전용 PNG 없이 절차적 바닥으로 표시된다.
- 기존 PNG는 128×128이며 `_draw_textured()`는 이미지 픽셀 크기대로 반복한다. 고해상도 원본을 그대로 바꾸면 원단 조직이 크게 확대된다. 텍스처 해상도와 월드 반복 크기를 분리하고, 우선 기존 128 월드 단위 반복 크기에서 비교해야 한다. 생성 이미지의 조직 밀도가 다르므로 최종 실 크기는 화면에서 조절한다.
- `FABRIC_BASE`는 새 이미지의 실제 평균색으로 갱신해 수평선과 원경 색이 끊기지 않게 한다. 주름의 바닥색 참조와 선택 화면 스와치도 같은 재질을 쓰는지 확인한다.
- 큰 주름은 이미지에 굽지 않고 기존 `DriftFoldLayer` 메시가 만든다. 이 파일은 normal/height/roughness map이 아니다.
- 양방향 반복을 목표로 생성했으나 픽셀 단위 무봉제는 보장하지 않는다. 적용 전 3×3 반복 경계와 Mode 7 원경의 모아레·반짝임을 확인한다. 필요하면 밉맵과 필터 설정을 함께 조절한다.
- 런타임 적용 및 실제 플레이 검증은 아직 수행하지 않았다. 재질별 주행 물리 값은 바꾸지 않는다.

## 주름 높이에 대한 의견

Claude의 `v230-folds/tune2.png` 캡처와 현재 `DriftSkid.gd`의 `FOLD_HEIGHT=2.6`을 확인했다. 정지 캡처에서는 손 옆 원단이 솟는 모습이 이미 읽힌다. 기본 높이는 유지하고, 강조가 필요하면 강한 드리프트의 정점만 약 3.0~3.2로 비교하는 것을 권한다. 이는 시각적 튜닝 제안이며 코드에 적용한 값이 아니다.

높이를 크게 올리면 손과 원단이 겹치고 재봉선이 가려질 수 있다. 새 텍스처를 적용한 뒤 같은 입력·카메라에서 비교해야 한다. 정지 캡처 기반 의견으로, 현재 애니메이션의 지속 시간과 실제 플레이 가독성까지 확인한 평가는 아니다.
